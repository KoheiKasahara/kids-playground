# 3Dクルマづくり 基本設計（Phase 1）

対応Issue: #401（Phase 1: 基盤・リアルタイムカスタマイズUI）

## 1. 目的

画面上部の3Dの車を見ながら、画面下部でカスタマイズを選ぶと、決定操作なしでその場で車が変わるあそび。

Phase 1 の目的は**完成版の車を作ることではなく、後続Issueで8カテゴリを独立して追加できる基盤を作ること**。
そのため、車両寸法・取り付け位置・カテゴリ差し替え構造を先に固定し、各カテゴリの造形は仮のままにしている。

- URL: `/games/car-builder`（プレイ画面1枚。ゲーム内で画面遷移はしない）
- 対象: 幼児（4〜5歳程度）。スマホ縦画面を最優先。

## 2. ファイル構成と責務

| ファイル | 責務 |
| --- | --- |
| `carConfig.ts` | カスタマイズ状態 `CarConfig` と、カテゴリ／選択肢のカタログ。three.js非依存 |
| `carDimensions.ts` | 車両寸法と attachment point の計算。純粋関数。three.js非依存 |
| `carParts.ts` | カテゴリ×選択肢ごとの3Dパーツ生成関数と登録表 |
| `carModel.ts` | レイヤー構造の組み立てと、CarConfig変更の差分反映・リソース解放 |
| `useCarBuilderScene.ts` | レンダラー／カメラ／ドラッグ回転・ピンチズーム／リサイズ |
| `CarBuilderPlay.tsx` | 画面。CarConfigとUI状態（一覧／詳細）を保持する |

依存の向きは `CarBuilderPlay → useCarBuilderScene → carModel → carParts → carDimensions → carConfig` の一方向。
`carConfig` / `carDimensions` は three.js を知らないため、単体テストで直接検証できる。

## 3. CarConfig

```ts
type CarConfig = { readonly [K in CarCategoryId]: CarOptionIdMap[K] }
```

- 全カテゴリを「カテゴリID → 選択肢ID」という同じ形で持つ。色も hex ではなく色ID（`red` など）を持ち、
  実際の塗り色は `resolveCarColor()` でカタログから引く。
  これにより、UIの更新も3D側の差分検出もカテゴリごとの分岐なしに書ける。
- 状態を持つのは `CarBuilderPlay` の `useState` 1か所だけ。3D側は `CarConfig` を受け取るだけで複製しない。
- 更新は `selectCarOption(config, categoryId, optionId)` のみ。カタログに無いIDや同じ値なら
  同じ参照を返し、不要な再描画とレイヤー再生成を起こさない。

## 4. 車両寸法（CarDimensions）

`computeCarDimensions(config)` が唯一の寸法の出どころ。ボディ／タイヤ／車高の3カテゴリだけが寸法へ影響する。

公開する値: 全長・車幅・全高・タイヤ込みの最大幅・ホイールベース・トレッド・タイヤ半径／厚み・
最低地上高（＝ボディ底面高さ）・ボディ下段の天面Y・ルーフ天面Y・キャビン寸法。

### 組み合わせ耐性

最低地上高は素の値をそのまま使わず、タイヤ半径に対して次の範囲へクランプする。

- 下限: `max(タイヤ半径 × 0.35, タイヤ上端 × 0.92 − ボディ下段の高さ)`
- 上限: `タイヤ半径 × 1.05`

これにより **大きいタイヤを選ぶと車体が自動的に持ち上がり**（＝タイヤが車体へめり込まない）、
**車高を下げても車体が地面へ潜らない**。トレッドも `車幅 + タイヤ厚 − 一定量` で決まるため、
タイヤを太くしても左右の位置関係が破綻しない。この不変条件は
`carDimensions.test.ts` がボディ×タイヤ×車高の全組み合わせで検証する。

## 5. Attachment point

`computeCarAttachments(dimensions)` が、各カテゴリのパーツが使う取り付け基準を返す。

| 名前 | 用途 |
| --- | --- |
| `front` / `rear` | ライト・グリル・ナンバー |
| `roof` | 屋根に乗せるパーツ |
| `sideLeft` / `sideRight` | 飾り・ステッカー |
| `wheels[]` | 4輪（位置・半径・厚み・前後左右） |

各 attachment は `position` / 外向き `normal` / 面の大きさ `size {width, extent}` を持つ。
パーツはこの3つだけを使って自分の位置と大きさを決め、**ボディ種別ごとの座標を持たない**。
座標系は「地面 y=0、車の前が +Z、原点は車体中心」。

## 6. 3D構造とリアルタイム反映

`createCarModel(config)` はカテゴリ単位のレイヤー（`car-layer-body` など）を作り、
`update(config)` で**変化したレイヤーだけ**を作り直す。

- レイヤーのキーは「選択肢ID + 寸法署名（ボディ/タイヤ/車高）+ 車体色」。
  寸法や色が変われば全パーツが作り直され、寸法へ自動的に追従する。
- 作り直したレイヤーの geometry / material は必ず `disposeCarObject()` で解放する。
- レイヤーを持たないカテゴリ（カラー・車高）は `CAR_DERIVED_CATEGORY_IDS` に登録し、
  「見た目を持つカテゴリ」と合わせて8カテゴリを必ず覆う（`carModel.test.ts` が検証）。
- `useCarBuilderScene` はシーンをマウント時に1回だけ作り、以降は差分更新のみ。
  描画は変化があったフレームだけ行い、requestAnimationFrame は1本、
  リスナーとthree.jsリソースはアンマウント時にすべて解放する。

## 7. 後続Issueでカテゴリを追加する手順

1. `carConfig.ts` の `CarOptionIdMap` に選択肢IDを足す（新カテゴリなら1行足す）。
2. `CAR_CATEGORIES` に表示定義（ラベル・アイコン・プレビュー）を足す。新カテゴリなら
   `CAR_CATEGORY_ORDER` と `DEFAULT_CAR_CONFIG` にも足す（漏れは型エラーかテストで落ちる）。
3. 見た目を持つカテゴリなら `carParts.ts` の `CAR_PART_BUILDERS` に生成関数を足し、
   新カテゴリなら `CAR_PART_CATEGORY_IDS`（または `CAR_DERIVED_CATEGORY_IDS`）へ登録する。
4. 寸法へ影響するカテゴリなら `carDimensions.ts` の spec 表へ行を足す。

UI・状態更新・3Dの差分反映・レイヤー解放はカタログ駆動のため、追加の作業は要らない。

## 9. 画面レイアウト

- 上部: 3D表示。残り高さをすべて使い、ドラッグで360°回転、ピンチ／ホイールでズーム。
  `touch-action: none` にして、3D操作とページのスクロール・ズームを競合させない。
- 下部: 高さ固定のカスタマイズエリア。カテゴリ一覧（4列×2行、横スクロールなし）と
  詳細選択が同じ場所で切り替わる。高さを固定しているのは、詳細へ入っても3D表示の高さが
  跳ねないようにするため。
- 詳細の「もどる」は大きく目立つ色にする。決定・適用ボタンは置かない。
- 低い横画面では8カテゴリを1行にし、タップ領域は44px以上を保つ。
