# 「いろまぜクイズ」基本設計

## 1. ゲーム概要と対象

2〜3つの絵の具を混ぜるとどんな色になるかを当てる4択クイズです。文字がまだ得意でない未就学児を主な対象とし、絵の具のイラストと色そのものだけで遊べるようにします。

バックエンドや外部APIは使わず、問題データ（色の16進数値）をすべてアプリへ同梱します。

## 2. 画面とURL

| 画面 | URL |
| --- | --- |
| 開始 | `/games/color-mix-quiz` |
| むずかしさ選択 | `/games/color-mix-quiz/level` |
| プレイ | `/games/color-mix-quiz/:level/play` |
| 結果 | `/games/color-mix-quiz/:level/result` |

`:level` は `easy` / `normal` / `hard` です。不正値はむずかしさ選択へ戻します。

```text
ホーム → 開始 → むずかしさ選択 → 10問プレイ → 結果
                    ↑                    │
                    └──── べつのむずかしさ ──┘
```

## 3. 難易度の定義（重要な原則）

以前の実装は、むずかしさが上がるほど4つの選択肢の見分けがつきにくくなる（ほぼ同じ色を並べる）方式でした。これは「色を見分ける視力テスト」であって「混色の理解を試すクイズ」になっておらず、また `hard` の元データが8問しかなく実質的に何度も同じ問題を繰り返すだけでした。

今回の設計はこの前提を変えます。

> **むずかしさは「選択肢の見分けにくさ」では決して上げない。「混色の広さ・複雑さ」で上げる。**

どのレベルでも、4つの選択肢は子どもが一目で区別できることを最低条件とします（具体的なしきい値は5章）。その代わり、レベルが上がるほど次の点で問題そのものが難しくなります。

- 使う絵の具の対象が増える（原色だけ → 二次色・白黒を混ぜる → 二次色同士や3色の複雑な混色）
- 答えの色が直感的に予測しにくくなる（暗くなる、彩度が落ちる、茶色系に寄るなど）
- （`hard` のみ、一部の問題に限り）選択肢の中に1つだけ、他より少し近い「本当に注意して見る」おとりを混ぜる

## 4. 出題プールとむずかしさの累積

出題プールは累積です（かんたん ⊂ ふつう ⊂ むずかしい）。各問題は「初出レベル」を1つ持ち、そのレベル以上のプールすべてに含まれます。

| レベル | 新規問題数 | 累積問題数 |
| --- | --- | --- |
| easy | 12 | 12 |
| normal | +10 | 22 |
| hard | +10（うち3色問題6） | 32 |

### 4.1 2色問題・3色問題

- 通常の問題は2つの絵の具を混ぜます。
- 3色の問題（3つの絵の具を混ぜる）は **hard だけの固有要素** です。easy・normal には一切登場しません。
- 見出しは `この {inputColors.length}しょくを まぜると？` で、2色なら「この 2しょくを まぜると？」、3色なら「この 3しょくを まぜると？」と表示します。

## 5. 絵の具モデルと入力パレットのルール

### 5.1 混色モデル

- `inputColors` に並んだ絵の具は、それぞれ「1単位」ずつ均等に混ざるものとして扱います。
- 二次色（オレンジ・みどり・むらさき・ピンク・みずいろ）は、それを作った原色2つに分解しません。したがって「みどり＋あか」と「あか＋あお＋きいろ」は別の問題として扱われ、それぞれに（両方とも妥当な）異なる答えを持たせられます。
- 3色の混色は、2色の混色に比べて相対的に白の割合が下がるため、同じ絵の具構成でも色が濃く出ます。例えば「あか＋きいろ＋しろ」（#28）は「オレンジ＋しろ」（#9）よりも濃いピーチ色になります。
- すべての結果色は、実際のポスターカラーで混ぜたときの見た目に近くなるよう、上記モデルを参考にしながら手作業で色を決めています（入力から自動計算はしません）。

### 5.2 入力パレットのルール（絵の具の世界の一貫性）

`inputColors` に登場できる値は次のどちらかに限ります。

1. 基本の絵の具5色（あか `#e94b3c` ／ きいろ `#f6d743` ／ あお `#3977c7` ／ しろ `#fffdf7` ／ くろ `#263238`）
2. 他のいずれかの問題の `resultColor`

つまり、子どもは「まだ出会っていない絵の具」を混ぜる問題には出会いません。二次色を混ぜる問題（#11〜#32）はすべて、より易しいレベルの問題で先に登場した色だけを材料にしています。この制約は `validateColorMixProblems` が機械的に検証します。

## 6. ΔE2000 によるしきい値と選択肢の設計

### 6.1 なぜ ΔE2000 か

RGBの単純なユークリッド距離は、人間が実際に色を見分けられるかどうかとあまり一致しません。色相・彩度・明度のどの軸にずれているかによって、同じRGB距離でも「一目で違うと分かる」場合と「ほとんど同じに見える」場合があります。そこで本ゲームでは知覚的な色差指標である **CIEDE2000（ΔE2000）** を採用し、`colorDifference.ts` に実装しています。すべてのしきい値はΔE2000（正解の色 vs 各おとりの色）で定義します。

### 6.2 しきい値

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `EASY_MIN_DELTA_E` | 25 | easy問題のおとりは必ずこれ以上離す |
| `NORMAL_MIN_DELTA_E` | 15 | normal問題のおとりは必ずこれ以上離す |
| `HARD_NEAR_MIN_DELTA_E` | 10 | hardのわざと近いおとりでも、これより近くはしない |
| `HARD_NEAR_MAX_DELTA_E` | 18 | 「近いおとり」とみなす上限（このレンジ内は最大1つまで） |
| `HARD_FAR_MIN_DELTA_E` | 25 | 近いおとり以外のhardのおとりは、これ以上離す |
| `MIN_CHOICE_PAIR_DELTA_E` | 10 | 4つの選択肢はどの2つを比べてもこれ以上離す（おとり同士も含む） |

hardでは、`[HARD_NEAR_MIN_DELTA_E, HARD_NEAR_MAX_DELTA_E]` の範囲に入るおとりを**最大1つまで**許容します。それ以外のおとりは必ず `HARD_FAR_MIN_DELTA_E` 以上離します。`(HARD_NEAR_MAX_DELTA_E, HARD_FAR_MIN_DELTA_E)` の間（このゲームでは18〜25）に落ちるおとりはデータ不備として扱い、片側に寄せます。

近いおとりは**任意**であり、32問中ごく一部（`purple-green` と `orange-purple` の2問）だけに、しかも2色問題にのみ用意しています。3色問題には near のおとりを一切使いません。3色問題のむずかしさは「3つ混ぜると何色か」という知識の広さそのものであるべきで、目の良さのテストにしてはいけないからです。

### 6.3 明示的に禁止する形

以前のhardで実際に起きていた「同じ色相で明るさだけが違う4枚」（例: むらさき／青みむらさき／赤みむらさき／もっと暗いむらさき）は禁止です。妥当なhardの選択肢パネルは、例えば「むらさき、少し青寄りのむらさき、みどり、オレンジ」のように、色相そのものが分かれている構成にします。

### 6.4 色覚特性への配慮

すべての問題について、少なくとも1つのおとりは正解と比べてL*（明度）が12以上離れていることをテストで保証します。赤緑を中心とした色覚特性を持つ場合でも、明るさの違いだけで少なくとも1択は判別できるようにするためです。

## 7. レベル別の own-tier クオータ

出題プールは累積のため、何も手当てしないと `hard` の10問はほとんどが easy 由来の問題になってしまいます（32問中10問をランダムに選ぶと、確率的にeasyが多数を占める）。そこで、そのレベルで新しく登場する問題（own-tier）を優先的に一定数確保してから、残りをプール全体からランダムに補充します。

| レベル | own-tier クオータ | 補足 |
| --- | --- | --- |
| easy | 0 | easyは初出問題しかなく、プールも小さいため循環で十分露出する |
| normal | 3 | 10問中最低3問はnormalで新規追加された問題 |
| hard | 4（うち3色問題2以上） | 10問中最低4問はhard新規、うち最低2問は3色問題 |

この割り当ては `generateColorMixQuestions` が問題数がプール以下の場合にのみ適用し、プールが問題数より小さく循環する場合（現状 easy の18問生成など）には適用しません（毎周回で全問題が出るため）。

## 8. 回答後の演出

- 正解・不正解に関わらず、絵の具が混ざるアニメーションを再生します。以前は正解時のみでしたが、混ざる様子を見せること自体がこのゲームの学習目的であり、間違えたときこそ見せる価値があるため変更しました。
- 「できた！」バッジは正解時のみ表示します。
- 不正解のときは、絵の具ステージの中に「えらんだいろ」（選んだ色）と「まざったいろ」（実際の正解の色）を並べて見せ、どれだけ違ったかを視覚的に比較できるようにします。この比較UIは `position: absolute` で絵の具ステージの中に重ねて表示し、画面下部のフィードバック領域用の余白（`--feedback-space`）や通常のレイアウトの高さ計算には影響しません。
- 効果音は変更していません。正解時はタップ直後の効果音＋少し遅れて鳴る正解チャイム、不正解時は不正解音のみです。

## 9. 将来拡張（今回は対象外）

分量の比率を伴う問題（例: 🔴🔴＋🔵のように「赤を多めに」混ぜる）は今回実装しません。ただし `ColorMixProblem.inputColors` を配列にしてあるため、将来的には次のいずれかの方法で自然に拡張できます。

- 同じ色を複数回並べる（例: `[RED, RED, BLUE]`）ことで「赤が多い」を表現する
- `inputColors` を `{ color: string; parts: number }[]` のような形に発展させる

UI側も `inputColors` を配列としてそのままマップして描画しているため、要素数が増えても絵の具ブロックの繰り返し描画で対応でき、大きな構造変更は不要な見込みです。

## 10. 検収条件

- `colorMixProblems` が32件、id・入力色の組み合わせが一意であること。
- easy 12件・normal（累積）22件・hard（累積）32件で、easy ⊂ normal ⊂ hard が成り立つこと。
- hard に3色問題が6件以上あり、easy・normalには3色問題が存在しないこと。
- easy/normal/hardそれぞれの新規問題が、6.2章のΔE2000しきい値をすべて満たすこと（`validateColorMixProblems()` が空配列を返す）。
- 4つの選択肢がどの2つを比べても `MIN_CHOICE_PAIR_DELTA_E` 以上離れていること。
- 各問題で少なくとも1つのおとりがL*で12以上離れていること（色覚特性ガード）。
- `generateColorMixQuestions` が各レベルで10問・4択・正解1件を返し、連続する2問が同じidや同じ結果色にならないこと（プール循環時も含む）。
- `hard` は複数回の実行で own-tier 4問以上・3色問題2問以上、`normal` は own-tier 3問以上を満たすこと。
- 回答後、正解・不正解どちらでも混色アニメーションが再生され、不正解時は「えらんだいろ／まざったいろ」の比較が表示されること。
- 3色問題では見出しが「この 3しょくを まぜると？」になり、絵の具ブロックが3つ表示されること。
- 既存の `lint`、全テスト、通常ビルド、Pagesビルドが成功すること。
