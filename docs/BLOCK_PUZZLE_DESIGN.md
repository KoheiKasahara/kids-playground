# ブロックパズル 設計（Phase 1 / #480）

## 目的・対象年齢

4〜5歳が説明なしで「かたちを えらぶ → ばんめんを タップ → そこに置かれる」だけで遊べる、自由配置型のパズルです。

テトリス風のブロック形状を使いますが、**落下しない・ラインは消えない・時間制限なし・ゲームオーバーなし・ランダム配布なし**という点で落下型パズルとは別物です。好きな形を何度でも選べるので「欲しい形が来ない」「詰んでやり直し」が起きません。1マスのブロックを常に選べるため、どんな置き方をしても最後は盤面を埋め切れます。

Phase 1（このドキュメントの範囲）では、盤面・ブロック形状・パーツ選択・基本配置と、後続フェーズのためのデータモデルまでを実装します。

## URLと画面遷移

難易度選択も結果画面も持たず、単一URLで完結します。

| 画面 | URL |
| --- | --- |
| プレイ（唯一の画面） | `/games/block-puzzle` |

```text
ホーム → ブロックパズル（かたちを えらぶ・ばんめんを タップして おく）→ もどる → ホーム
```

CSSグリッドと純粋なロジックだけで動き、3D・物理エンジンのような重い依存を持たないため、うごくぬりえと同じく遅延読込（`React.lazy`）にはせず `routes.tsx` へ静的importで登録しています。

## 盤面サイズ（6×8を採用した理由）

候補の 6×8 / 7×8 / 8×8 を実画面（Playwright・390×844のスマホ縦）で比べ、**6列×8行**を採用しました。

| 盤面 | スマホ縦での1マス |
| --- | --- |
| 6×8（採用） | 59px |
| 7×8 | 51px |
| 8×8 | 44px |

規約（`docs/MINIGAME_DEVELOPMENT_GUIDELINES.md`）の「主操作のタップ領域は原則64px以上」に最も近づけられるのが6列で、48マスあれば9種類のブロックを何個も並べる遊びとして十分な広さがあります。マス数を増やすほどパズルらしくはなりますが、1マスが小さくなって幼児のタップ精度に合わなくなるため増やしていません。正方形の8×8はスマホ縦では上下に大きな余白が残り、画面の使い方としても縦長の6×8が有利でした。

盤面の大きさは JavaScript での計測ではなく、コンテナクエリ単位（`cqw` / `cqh`）1つの式で「余っている幅と高さの両方に収まる最大サイズ」を求めています。横スクロールは発生せず、320px幅の狭い縦画面でも主要UIが1画面に収まります。低い横画面（`orientation: landscape` かつ高さ560px以下）ではパーツ一覧を右側の縦並びに移し、余った高さを盤面へ渡します。

## ブロックの形と色

9種類。形ごとに色を固定しているので、同じ形は何度選んでも必ず同じ色です。

| 形 | id | マス数 | 色 |
| --- | --- | --- | --- |
| 1マス | `single` | 1 | あか `#ff6b6b` |
| 2マス | `duo` | 2 | オレンジ `#ffa94d` |
| ながいぼう（I型） | `i` | 4 | きいろ `#ffd43b` |
| しかく（O型） | `o` | 4 | みどり `#51cf66` |
| ティーのかたち（T型） | `t` | 4 | ティール `#38d9a9` |
| エルのかたち（L型） | `l` | 4 | あお `#4dabf7` |
| ジェイのかたち（J型） | `j` | 4 | むらさき `#845ef7` |
| エスのかたち（S型） | `s` | 4 | きみどり `#a9e34b` |
| ゼットのかたち（Z型） | `z` | 4 | ピンク `#f06595` |

- 1マスは必須の救済パーツで、初期選択もこれにしています（開いてすぐ意味が分かるため）。
- 取り違えやすい鏡像ペア（L/J・S/Z）には離れた色相を割り当て、形が似ていても色で見分けられるようにしています。
- 落下型ゲームの慣習的な配色はコピーせず、kids-playgroundのトークンに合う明るい色で揃えています。

## データモデル（#481 / #482を見越した設計）

盤面の正本は「どのマスが何色か」のセル配列ではなく、**配置済みブロックの配列**です。責務ごとにファイルを分けています。

| ファイル | 責務 |
| --- | --- |
| `board.ts` | 盤面のマス目だけ（サイズ・内外判定・マスのキー） |
| `blockShapes.ts` | 形の定義だけ（相対セル・色・向きの計算） |
| `placement.ts` | 配置済みブロックと配置可否の判定 |
| `blockPuzzleState.ts` | 画面全体の状態と、その非破壊な更新 |
| `blockRendering.ts` | 「1つのまとまったパーツ」に見せるための形の計算（純粋関数） |
| `BlockPiece.tsx` | ブロック1個の見た目（盤面とパーツ一覧で共有） |
| `BlockPuzzlePlay.tsx` | 画面の組み立てと入力の受け付け |

```ts
type PlacedBlock = {
  id: string            // 一意なID（#481の選択・移動・削除の鍵）
  shapeId: BlockShapeId // ブロックの種類
  anchor: BoardCell     // 基準セルの絶対位置
  rotation: BlockRotation // 0 | 90 | 180 | 270（Phase 1では常に0）
}
```

占有マスは保存せず `placedBlockCells()` で毎回導出します。保存しないことで、`anchor` や `rotation` を書き換えるだけで移動・回転が成立し、占有マスとの食い違いが構造的に起きません。

- **#481（配置済みパーツの選択）**: `cellOwners()` が「マス → ブロック」の対応表を返すので、タップされたマスからブロックを引けます（Phase 1でもマスの読み上げラベルに使用中）。
- **#481（回転）**: `rotation` の居場所と `rotateOffsets()`（基準セルまわりの時計回り）はすでにあり、値を変えるだけで形が変わります。盤面上の見た目の位置を保つ基準位置の取り直しは #481 側の責務です。
- **#481（移動）**: 元位置の解放は「配列から取り除いて置き直す」だけで済みます。占有マスは常に導出なので、解放し忘れが起きません。
- **#481（削除）**: `id` で配列から除くだけです。
- **#482（完成判定）**: `occupiedCellKeys(blocks).size === BOARD_CELL_COUNT` で全マス占有を判定できます。

Phase 1では回転・移動・削除・完成判定の**操作は実装しません**（Issue #480の非目標）。上記は「後から足せる形にしてある」という設計上の担保です。

## 配置の基準点

パーツ選択後に盤面のマスをタップすると、**そのマスがブロックの基準セル(0,0)になります**。

基準セルは各形の「読み順（いちばん上の段の、いちばん左の占有セル）で最初のセル」と定義し、すべての形が基準セルを自分の占有セルとして含むことをテストで固定しています。これにより**タップしたマスは必ずブロックの一部になる**ため、「押した場所と違うところに出た」と見えることがありません。

L型・S型は基準セルより左へ伸びるため相対セルの `col` が負になりますが、盤面内かどうかは `placement.ts` が判定するので形の定義は素直なままです。

## 配置判定

- 盤面内で、既存ブロックと重ならなければ置ける
- 盤面外へはみ出す位置には置けない
- 1マスでも重なる位置には置けない
- 同じ形は何個でも置ける（1マスも含めて消費という概念がない）

置けなかったときは**失敗扱いにしません**。ゲームオーバー・失敗画面・パーツ消費はなく、タップしたマスに赤い枠を出し、`role="status"` の一行を「ここには おけないよ」に変えるだけです。赤枠は時間で消さず次の操作まで残すので、幼児が見返しても状況が分かります（配置済みブロックの下に隠れないよう、ブロックと同じ重ねレイヤーのいちばん上に描いています）。

## 見た目

- 盤面のマスは、白い角丸と中央の小さな点で「へこんだ穴」に見せ、ここにブロックをはめると分かるようにしています。
- ブロックは外周の辺にだけ濃い輪郭と丸みを付け、内側の継ぎ目は細い白線にとどめています。バラバラの四角にも、のっぺりした一枚の面にも見えないようにするためで、この計算は `blockRendering.ts` の `cellEdges()` に集約し、盤面とパーツ一覧で同じ関数を使っています。
- 選択中のパーツは「太い枠・背景色・拡大・チェックマーク」を重ねて示し、文字を読まなくても分かるようにしています。

## アクセシビリティ

- 盤面の各マスは標準の `<button>` で、`よこ2 たて3 しかく` のように位置と中身を読み上げます（空きは `あき`）。
- パーツ一覧は `role="group"` + `aria-pressed` で、いまどれを選んでいるかを伝えます。
- 配置できなかったことは色だけでなく `role="status"` / `aria-live="polite"` の文言でも伝えます。
- 装飾の絵文字・チェックマーク・重ねレイヤーは `aria-hidden="true"` です。
- `prefers-reduced-motion` ではタップ時の縮小アニメーションを止めます。
