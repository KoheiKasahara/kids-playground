# 3Dどうぶつえん 動物制作ガイド

> この文書は「3Dどうぶつえん」（`src/games/zoo-3d/`）に動物を追加するときの標準仕様と手順を定めます。
> 実際の値・動きは生成スクリプト（`scripts/zoo-3d/`）と生成物、テスト（`src/games/zoo-3d/*.test.ts`）を正とします。
> この文書と実装がずれたら、実装とテストを確認してから、この文書を直してください。
> AI エージェントは Skill `zoo-animal-creator`（`.agents/skills/zoo-animal-creator/`）から、この文書を手順書として使います。

動物の形・骨格・モーションは手作業で作りません。Blender の Python スクリプトで生成し、スクリプト・`.blend`・GLB をリポジトリで管理します。
ゾウ・キリン・ライオン（PR #1046）とパンダ（このガイドの検証で追加）が、この方式で作られた成功例です。

## 1. 制作の流れ

```
動物の特徴を調べる
  → scripts/zoo-3d/new_animal.py で体型の近い動物から土台をコピー
  → zoo3d/animals/<id>.py（形・色・骨格）と <id>_motion.py（動き）を書き換える
  → scripts/zoo-3d/build.sh <id>           … GLB・モーション情報 JSON・.blend を生成し、足の滑り量を表示
  → render_clip.py / lineup.py で見た目と動きを確認（直す → 生成し直す、をくり返す）
  → src/games/zoo-3d/ に登録（species.ts・zooMap.ts ほか）
  → テスト・ブラウザでの確認・npm run verify
```

| 項目 | 内容 |
| --- | --- |
| Blender | 4.5 LTS。`scripts/zoo-3d/setup-blender.sh` が版を固定して取得し、SHA-256 を検証する。GPU は不要（クラウドの CPU で動く） |
| 実行 | `blender -b --factory-startup --python scripts/zoo-3d/build_animal.py -- --animal <id>`（`build.sh` が呼ぶ） |
| 後処理 | glTF Transform（`npx @gltf-transform/cli@4.5.1`）で `resample`・`prune`・`meshopt` 圧縮。`package.json` には追加しない |
| QA の描画 | Cycles（静止画）と Workbench（連番・動画）。Workbench には EGL（Mesa の `libegl1` `libgl1-mesa-dri`）が必要 |
| 外部素材 | 使わない。例外は Mesh2Motion（CC0）のモーションで、`scripts/zoo-3d/vendor/mesh2motion/` に出典つきで置く |

## 2. アートスタイル

- **かわいい、ずんぐりしたローポリの「ソフトビニール人形」調**。輪郭は丸く、陰影はスムーズシェーディングです。三角形数は少なめでも、角ばらないようにします。
- **大きな頭、短めでしっかりした脚**。実際の動物より頭を大きくし、子どもが顔を見分けやすくします。
- **目**は黒い縦長の楕円に、白いハイライトを1つ付けます。目のまわりが黒い動物（パンダ）は、白目を敷いて目を読めるようにします。
- **頬**には淡いピンクの丸を付けます。鼻・爪・耳の内側も小さな「デカール」（表面に沿う薄い楕円体）で付けます。
- **色**は頂点カラーのみで、テクスチャは使いません。彩度は少し抑えた明るい色にし、模様（キリンのぶち・パンダの帯）は形として重ねます。
  色の境目をギザギザにしないため、面ごとの塗り分けで模様を作りません（下の「造形の作り方」を参照）。
- **一目で種類が分かる特徴を1〜3つ**、誇張して入れます（ゾウの鼻と耳、キリンの首とぶち、ライオンのたてがみ、パンダの白黒）。
- 既存の動物と並べて違和感がないことを、`scripts/zoo-3d/lineup.py` の比較画像で確かめます。

## 3. 標準仕様（すべての動物に共通）

### 3.1 座標・単位・向き

- Blender は Z-up で、動物の前方を **-Y**、単位はメートルにします。GLB に書き出すと Three.js の Y-up・前方 **+Z** になります。
- 動物の左右は「動物から見て」です。左が **+X**（骨名の `_l`）、右が **-X**（`_r`）です。
- 原点は4本（2本）の足の中央・地面の高さに置き、足の裏が `z = 0` に接するようにします。
- 大きさは、ゲーム内での見た目の関係（キリン ＞ ゾウ ＞ ライオン ≒ パンダ）が実物と大きく矛盾しないように決めます。子どもの個体はゲーム側で縮小します（`members[].scale`）。

### 3.2 造形の作り方と品質基準

- **体は符号付き距離関数（SDF）で定義**します。楕円体・テーパー付きカプセル・カプセルの連なりを、なめらかな和（`blend`）で合成し、Surface Nets でメッシュ化してから減面します（`zoo3d/sdf.py`, `zoo3d/meshing.py`）。
  - `Body(floor=0.0)` で足の裏を平らにします。
  - 模様を形の「共通部分」で切り出すときは `ellipsoid(..., intersect=True)` を使います（パンダの肩の帯）。
- **色の境目は形で作ります**。
  - 耳の内側・頬・鼻・爪・ぶち・目のまわりは、表面に沿うデカール（`meshing.decal`）にします。
  - 黒い脚や帯のように大きい模様は、白い体に重なる別の形（パンダの `black_parts()`）にします。
  - 面ごとの塗り分け（`paint` の領域）は、部位全体を1色にするときだけ使います。
- **部品の役割**（`zoo3d/creature.py` の `assemble`）:
  - `body`: 自動ウェイト（bone heat）を付ける本体。複数あれば結合してから付けます。
  - `decal`: いちばん近い本体の頂点のウェイトを写します（たてがみ・爪・ぶち）。
  - `rigid`: 1本の骨に固定します（きば・鼻・目のまわり模様・頬）。
  - `chains`: 骨の並びに沿って配分します（ゾウの耳のような板状の部位）。
  - `eye_l` / `eye_r`: 目の骨へ固定します（まばたきで縦に縮めるため）。
- **品質基準**
  - 正面・斜め前・横・斜め後ろ・後ろ・上の6方向（`qa.VIEWS`）すべてで、輪郭が崩れず、継ぎ目・穴・飛び出した面がないこと。
  - 箱や球の組み合わせに見えないこと。部位どうしは `blend` でなめらかにつなぎます。
  - 三角形数は1体あたりおおむね **9,000 未満**です（`models.test.ts` が検査）。既存の動物は約 6,000〜7,400 です。
  - 1頂点あたりのウェイトは最大4本です（`rig.limit_influences`）。マテリアルは頂点カラー1つで、描画呼び出しは1体1回です。

### 3.3 骨格の標準

骨の名前と親子関係は、Mesh2Motion の四足テンプレートに合わせます（リターゲットの対応表を単純に保つため）。
骨のローカル X 軸は、なるべく動物の左（+X）へ向けます（`rig.BoneSpec.lateral`）。左右対称の骨は `_l` で定義し、`rig.with_mirrors` で `_r` を作ります。

| 骨 | 必須 | 役割 |
| --- | --- | --- |
| `root` | ○ | 原点。ゲームが動物全体を動かすので、アニメーションでは動かさない |
| `hips` → `spine_1` → `spine_2` | ○ | 腰・背中・胸（肩）。上下動・左右の揺れ・ねじれを受け持つ |
| 首（`neck` または `neck_1`…） → `head` | ○ | 首が長い動物は本数を増やす（キリンは3本） |
| `eye_l` / `eye_r` | ○ | まばたき用。スケールの Z を縮めて閉じる（`Blink` が使う） |
| `ear_l` / `ear_r` | 動物による | 耳のぴくぴく・ぱたぱた |
| `tail_1`… | 動物による | 尾の揺れ（本数は尾の長さに合わせる） |
| `front_leg_{upper,lower,foot}_{l,r}` / `back_leg_{upper,lower,foot}_{l,r}` | 四足○ | 2本骨 IK（上・下）＋足先。中間の関節は休止姿勢でもわずかに曲げておく（足を前後に出す余裕を作るため） |
| `leg_{upper,lower,foot}_{l,r}` | 二足○ | 二足・鳥の脚（`bodyplan.Config(plan='biped')`） |
| 変形に使わない補助の骨 | 任意 | 物を持つ位置・効果の出どころ（ゾウの `trunk_tip`、パンダの `hold_r`）。GLB に書き出され、ゲームが名前で探す |

### 3.4 アニメーションの標準

**必須クリップ**（`models.test.ts` が名前と長さを検査します）:

| クリップ | ループ | 内容 |
| --- | --- | --- |
| `Idle` | ○ | 待機。呼吸・体重移動・頭の見回し・耳と尾の動き・まばたきを入れ、足は IK で固定する |
| `Walk` / `WalkLeft` / `WalkRight` | ○ | 直進と、1周期で左右へ曲がる歩き。周期・位相をそろえ、ゲームが旋回の速さで混ぜる |
| `Run` | ○ | 走り。歩きより周期を短く、歩幅・持ち上げを大きくする |
| `TurnLeft` / `TurnRight` | ○ | その場の方向転換（足を踏みかえながら回る） |
| `Eat` | × | 食事。`food`（持つ骨・つかむ／食べ終わる時刻・届く距離）をモーション情報に書く |
| `LieDown` / `Sleep` / `GetUp` | ×／○／× | 伏せる・眠る（目を閉じて呼吸）・起きる。`GetUp` は `LieDown` を逆再生して作る |
| `Happy` | × | なでられたとき・食べたあとの反応。目を細め、はずむ |
| `Blink` | × | まばたきの重ねがけ用。`meta.bones = ['eye_l', 'eye_r']` で目の骨だけを持つ |

**固有アクション**: 動物ごとに1〜2種類作ります（`kind: 'special'`）。
- 鳴き声は `sound` と `callStart` / `callEnd` で指定します。
- 水しぶきなどの効果は `effect` と骨名（`bone`）で指定します。ゲームはその骨から効果を出します（指定がなければゾウの鼻先 `trunk_tip`）。

ゲームはこれらの情報を読んで、音・音符・水しぶきを出します。

**作り方**（`zoo3d/anim.py`, `zoo3d/bodyplan.py`）:
- 時刻→姿勢の関数（`Clip.sample`）を毎フレーム評価し、30fps で焼き込みます。
- 回転は、休止姿勢の骨格空間の軸まわりで指定します（`Pose.rot`）。
- 足は IK で置きます（`plant_feet` で固定する、`place_feet` で歩容に従わせる）。
- Mesh2Motion のモーションを使うときは、`retarget.py` で骨格空間の回転差分を写します。足は元の動きを使わず IK で置き直します。
- 写すと形が破綻するときは、効きの強さ（`strength`）を調整します。それでも破綻する部位（たてがみ・長い首など）は、手続きの動きに切り替えます。

### 3.5 歩容と足滑りの基準

- 歩き・走り・方向転換は `Gait`（各脚の位相・接地率・1周期の移動量／旋回量）から足首の軌道を求め、IK で脚を合わせます。
  - 接地中の足は地面に対して静止させます。
  - 遊脚の水平移動も地面基準でイーズさせます（着地の瞬間に滑らない）。
- **足滑りの基準**: `build.sh` が表示する `max slide`（接地1回あたりの足裏の移動量）と `IK reach error` が、すべての歩容で **1mm 未満**です（既存の動物はすべて 0.0〜0.1mm）。
  - 超えたときは、`crouch`（胴を下げる量）を増やすか、歩幅・接地率を減らします。脚が伸び切って IK が届いていない合図です。
- 位相のひな形は `bodyplan.GAITS` にあります。動物の歩き方に合わせて選びます。

| 名前 | 使う動物の例 |
| --- | --- |
| `lateral_walk` | ゾウ・ライオン・パンダの常歩 |
| `pace` | キリン・ラクダ |
| `gallop` | 走り |
| `bound` | ウサギ・リス |
| `biped_walk` / `biped_hop` | 二足・鳥 |

- ゲームは、モーション情報 JSON の `distancePerCycle` / `turnPerCycle` から移動・旋回の速さを決め、再生速度を同期させます（`motion.ts`, `animator.ts`）。この値は焼き込み時の実際の長さ（フレーム数 / 30）から計算され、書き出し後に変わりません。

### 3.6 書き出し（GLB とモーション情報）

- `zoo3d/export.py` の `export_glb` を使い、設定を変えません。主な設定は次のとおりです。
  - 頂点カラーは `ACTIVE`、法線あり、UV・テクスチャなし。
  - 全アクションを NLA から書き出す（`export_animation_mode='ACTIONS'`）。
  - 毎フレームでサンプリングする（`export_force_sampling`）。
  - Y-up。
- **フレームレートは 30fps** です（`build_animal.py` がシーンに設定）。Blender の既定（24fps）のまま書き出すと、クリップの長さが 1.25 倍にずれます。
- 後処理で `resample` → `prune` → `meshopt`（high）をかけます。ゲームは Three.js 同梱の `MeshoptDecoder` で読みます。
- モーション情報 JSON（`src/games/zoo-3d/models/<id>.json`）の内容は次のとおりです。
  - クリップごとの `duration`・`loop`・`kind` と移動量。
  - 食事の `food`。
  - 体の大きさ `bounds`。
  - 三角形数。

### 3.7 ゲームへの組み込み

| 場所 | 追加すること |
| --- | --- |
| `src/games/zoo-3d/species.ts` | `SPECIES` に定義（名前・絵文字・色・モーション情報・えさ・固有アクション・説明3つ・届く距離・タップ判定の球・追従カメラ・個体（親子）・ふるまいの傾向）を足し、`SPECIES_ORDER` に加える |
| `src/games/zoo-3d/zooMap.ts` | その動物が暮らすエリア（サバンナ・もうじゅうの もり など）を選び、展示場を置く。体の大きさ・くらし方が近い動物は、既存の展示場の `species` に加えて同じ展示場に入れてよい（サバンナ・ふれあい広場）。新しい展示場は、中心・半径・柵の種類（`barrier`: 堀・ガラス・おり・岩のかべ・木のさく）・地面の色・池・木・岩・獣舎を決め、ほかの展示場・園路・広場と重ならない位置に置く（`zooMap.test.ts` が検査） |
| `src/games/zoo-3d/effects.ts` | 新しいえさの形が必要なら `FoodKind` と `createFood` に追加する |
| `src/games/zoo-3d/scenery.ts` | 新しい木の種類が必要なら追加する（カメラがよける球も登録する） |
| `src/games/zoo-3d/sounds.ts` | 鳴き声が必要なら追加し、`src/test/audio/gameSoundSamples.ts` に代表音として登録する |
| `docs/credits.md` | 出典（Mesh2Motion を使ったらファイル名） |

- **行動 AI**（`behavior.ts`）は全動物で共通です。動物ごとの違いは、`species.ts` の `mood`（待機時間・歩く・走る・食べる・固有アクション・眠る・人を見に来る `curious` の重み）と、モーション情報の速さで表します。
  - 子ども（`members[].scale` が小さい個体）は親のそばへついて行き、えさを食べたあとは、お礼に固有アクションを見せることがあります。
  - 固有アクションは、ボタンでさせるのではなく、動物が自分でしているところを見つけると「ずかん」のスタンプになります（`zukan.ts`）。観察して見つけられる頻度になるよう `mood.special` を決めます。
- **持ち運び**: 食べ物を骨に付けて運ぶ動物は、`Eat` の `food` に `bone`（GLB の骨名）と `hold: true` を書きます。エンジンがその骨を探して動かします。
- **タップ判定**: 動物の前方 +Z を基準にした球で行います（`hit`）。頭と胴を覆うように置きます。

### 3.10 性能・容量の目標

- **iPhone の Safari で 60fps を目標、最低 30fps**。
- **1体**: 三角形 9,000 未満、骨 40 本程度まで、テクスチャなし、描画呼び出し 1 回。
- **GLB は圧縮後 1体あたりおおむね 500KiB 以下**です（既存は 約 320〜460KiB）。
  - クリップを増やしすぎないようにします。固有アクションは 1〜2 種類、1本あたり 5 秒以内が目安です。
- **園全体**: 園はいくつかのエリアに分かれ、1度に1つのエリアだけを読み込んで描きます（`zooMap.ts` の `AREAS`、`areaStage.ts`）。
  - 動物を増やすときは、1つのエリアの動物がおおむね十数頭に収まるようにします。多くなるときはエリアを分けます。
  - 読み込んだ GLB は覚えておき、エリアを行き来しても読み直しません。エリアを出るときは、そのエリアの動物の GPU の資源を手放します。
  - 影は太陽1灯で、影を落とす範囲をエリア（歩くモードでは人のまわり）にしぼります。
  - 景色は1メッシュ、ガラスは1メッシュ、池と堀の水面は1メッシュ、波紋は1つの InstancedMesh、看板は1枚のテクスチャにまとめます。
  - 画面外の動物は描かず（スキンメッシュは視錐台カリングを切っているため、`useZooEngine.ts` で判定）、小さく映る動物は影を省いてアニメーションの更新を間引きます。
  - 重い端末では解像度を下げます（`useZooEngine.ts`）。
- **PWA**: GLB は全てプリキャッシュされ、オフラインで遊べます。
  - `npm run build` の `check:loading` で、初期読み込みの予算と保存容量の増加を確認します。
  - 警告が出たら、増えた内訳を PR で説明します。基準値は、検査を通すためだけには変えません。

## 4. 体型ごとの違い（ボディプラン）

すべての動物に同じ骨格・同じ動きを当てはめません。`bodyplan.Config` の `plan` と脚の骨名で体型を選び、動物固有の部位は個別に足します。

| 体型 | 例 | 骨格の違い | 動きの注意 |
| --- | --- | --- | --- |
| 四足・柱のような脚 | ゾウ | 脚はまっすぐに近い。休止姿勢で中間の関節をわずかに曲げて、IK の余裕を作る | 胴を脚で運ぶように上下させ、歩幅は小さめにする |
| 四足・蹄・長い首 | キリン | 首を3本以上にする。前脚のひざは前、後ろ脚の飛節は後ろへ曲がる（`front_pole` / `hind_pole`） | 歩きは側対歩（`pace`）。首を歩調に合わせて前後に揺らし、地面の物を食べるときは前脚を開く |
| 四足・趾行（つま先立ち） | ライオン、イヌ、ネコ | 後ろ足の足先の骨を長くして、かかとを浮かせる | 肩を上下に転がすように歩く。走りは背中をしならせる（`spine_flex`） |
| 四足・蹠行（かかとをつける） | パンダ、クマ | 足先は短く、かかとまで接地する。前足で物を持つなら補助の骨（`hold_r`）を置く | 腰を左右に大きく揺らしてのっしのっし歩く（`roll` を大きく）。座って前足を使う動作は、後ろ足を IK で固定し、前足を口元の目標へ向ける |
| 特殊な部位 | ゾウの鼻 | 部位に骨の並びを通す（鼻は7本＋先端の補助の骨） | 部位の動き（振り子・巻き上げ）を専用に書く（`elephant_motion.py`） |
| 四足・はう | ワニ | ひじ・ひざを体の外へ張り出す。`Config(pole_mirror=True)` で右の脚の pole を左右反転する | 体の長さに対して脚が短いので、旋回量を小さくして `crouch` を増やす。体を左右にくねらせ（`roll`）、尾を大きくふる |
| 二足・鳥 | ペンギン、ダチョウ、フラミンゴ | 脚は `leg_{upper,lower,foot}_{l,r}`（`plan='biped'`）。翼は `wing_*` などの骨の並びにし、歩容には含めない | 歩きは `biped_walk`、跳ねは `biped_hop`。胴の左右の揺れ（`sway`・`roll`）を四足より大きくする。翼の動き（羽ばたき・広げる）は固有アクションとして書く |

二足の歩容が足を滑らせないことは、`scripts/zoo-3d/selftest.py`（棒人形での自己診断）で確認できます。
この自己診断は、四足・二足の両方の骨格で歩き・曲がり歩き・走り・跳ね・方向転換を生成し、足滑りが 1mm 未満であることを検査します。

## 6. 動物の追加手順

1. **特徴を調べる**: 次の点を整理して、上の個別仕様表に1行足します。
   - 体型・大きさ（既存の動物との比）。
   - 一目で分かる特徴（1〜3つ）と色。
   - 歩き方（位相・接地率・歩幅の印象）。
   - 食べ方、固有アクション（1〜2種類）、鳴き声。
2. **土台を作る**: `python3 scripts/zoo-3d/new_animal.py <id> --like <近い動物>` を実行します。
   - 首が短い四足は `lion`、長い首は `giraffe`、特殊な部位は `elephant`、前足を使う四足は `panda` を選びます。
   - 二足・鳥は、`panda` か `lion` を土台に脚を `plan='biped'` の骨名へ置き換えます（`selftest.py` の骨格を参照）。
3. **形を作る**: `<id>.py` の `body()`・色・デカール・`bones()` を書き換えます。
   - 6方向の画像を見ながら直します（下の検証を参照）。
   - 中間の関節の曲げ・`hold` などの補助の骨もここで決めます。
4. **動きを作る**: `<id>_motion.py` で、`Idle`・`Walk`（左右）・`Run`・`Turn`・`Eat`・`LieDown`/`Sleep`/`GetUp`・`Happy`・`Blink` と固有アクションを作ります。
   - Mesh2Motion を使うときは、展開した GLB を `vendor/mesh2motion/` に置き、`SOURCE.md` に追記します。
5. **生成する**: `scripts/zoo-3d/build.sh <id>` を実行します。全歩容の `max slide` と `IK reach error` が 1mm 未満になるまで直します。
6. **ゲームへ登録**: 3.7 の表のとおりに追加します。
7. **検証**: 下の 7 章をすべて行い、問題があれば 3〜6 に戻ります。
8. **記録**: 個別仕様表と `docs/credits.md` を更新します。

## 8. 成功事例から得た注意点

実際の制作で起きた問題と対処です。同じ失敗を避けるために守ります。

- **フレームレート**: 24fps のまま書き出し、全クリップが 1.25 倍の長さになった。`build_animal.py` がシーンを 30fps にする。
- **まばたきが全身を休止姿勢へ戻す**: glTF は全骨を書き出すため、`Blink` を重ねると体が引き戻された。`meta.bones` で目の骨だけに絞り、ゲーム側でもトラックを絞る（`animator.overlayClip`）。
- **足が届かず滑る**: 脚がまっすぐな休止姿勢だと、足を前後に出したときに IK が届かない。中間の関節を休止姿勢で曲げ、`crouch` で胴を下げる。
- **リターゲットの破綻**: キツネの丸まった睡眠をライオンへ写すと、たてがみが顔を覆った。キリンで首の強さを上げると、首が C の字に折れた。前者は手続きの伏せに切り替え、後者は首の付け根だけを追加で倒した。
- **模様が見えない**: パンダの肩の帯を胴だけから切り出したため、胸の膨らみの内側に埋もれた。模様の外形は、白い体を構成する形すべてを少し膨らませて作る。
- **追従カメラが隠れる**: 竹やぶが動物とカメラの間に入った。視界をさえぎる物は球として登録し、`cameraRig.followAzimuth` で避ける方向へ回り込む。
- **エリアの重なり**: 動物を足すと柵が重なりやすい。`zooMap.test.ts` が重なりを検査する。
- **熱拡散のウェイトが解けない**: シマウマのしま（細かい島がたくさんある殻）を本体と一緒に自動ウェイトの対象にしたら、Blender が「Bone Heat Weighting: failed」を出し、体がまったく動かなかった。しまのような薄い殻は `decal`（体の最寄りの頂点からウェイトを写す）にする。`build.sh` はこの警告と、ウェイトのない頂点の数（`WARNING`）を表示する。
- **長い首の動物の食事**: アルパカ（まっすぐ立った長い首）に馬の Eating を写すと、体ごと前へ倒れた。胸を少し下げ、首をまっすぐのまま付け根から前へ倒す手続きの動きにし、倒す角度は口が地面に届くよう二分探索で決める。首が脚より短いと地面に届かないので、首の長さも見直す。
- **点がたくさんある模様**: チーターの点を `C.spots`（1つ約80三角形）で70個貼ると、三角形数の上限（9,000）を超えた。点のデカールは分割を減らして軽くする（1つ約40三角形）。
- **歩容クリップに後から動きを足すとき**: ペンギンの走りで、IK のあとに腰（`hips`）を回したら足が滑った。足の IK を変えない骨（背骨より上・ひれ）だけを足す。
