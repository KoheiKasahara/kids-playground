# 「こっきコロコロぼうけん」基本設計

## 概要

「こっきコロコロぼうけん」は、国旗そのものが球に見える「国旗ボール」を1個選び、4エリアのアスレチックコースを操作せずに見守るミニゲームです。ボールは空・森・洞窟をゆっくり転がり、最後にゴールへ集まります。得点・ランキング・時間計測は持たず、国旗を選ぶ楽しさと、球が動く様子を眺める楽しさに絞ります。

この文書と実装はPhase 1（最小プレイアブル版）の範囲です。Phase 1では4エリア、1本の経路、CSSだけの仮背景、matter-jsによる1球の物理演算だけを実装します。分岐・大砲・逆重力・本番背景素材・10エリア以上・派手な演出はこの段階では扱いません。

## 画面と進行（URL）

| 画面 | URL |
| --- | --- |
| 国旗選択 | `/games/flag-roll-adventure` |
| プレイ | `/games/flag-roll-adventure/play` |
| ゴール | `/games/flag-roll-adventure/goal` |

```text
ホーム → 国旗選択（1個選ぶ）→ プレイ（4エリアを見守る）→ ゴール → もういっかい／べつの こっき
```

選択画面では40個の国旗ボールから1個だけを選びます。プレイ画面へは`{ flagId }`を、ゴール画面へも同じ`{ flagId }`を画面遷移stateで渡します。`playState.ts`の型ガードは、既知のflagIdを1つだけ持つstate以外を拒否します。stateなし・不正なstateでプレイ／ゴールURLを直接開いた場合は、選択画面へ`replace`で戻します。

matter-jsを含むため、3画面は`routes.tsx`の`lazyRoute(() => import(...))`で遅延読込します。ピンボールと同じく、ホームや他の軽いゲームの初期chunkへ物理エンジンを混ぜないためです。

プレイ画面は`key={location.key}`を付けた内部コンポーネントで構成します。「もういっかい」で同じ国旗を選び直さなくても、物理世界・カメラ・訪問履歴・ゴールタイマーを丸ごと作り直せるようにするためです。

## 国旗ボールの共通化

`src/components/flag-ball/`に`FlagBall`と`flagBalls`を置き、こっきピンボールと本ゲームで共有します。国旗データは既存の`flag-quiz/data/countries`をマスターとして参照し、40個のidと円形クロップ用の`ballPositionX`だけを共通データへ持たせます。新しい国旗画像は追加しません。

既存の`src/games/flag-pinball/data/pinballFlags.ts`は、既存のimportとテストを壊さないための互換re-exportとして残します。`PinballFlag`も`FlagBallData`の別名にし、ピンボール側の型名とシグネチャを必要以上に変更しません。ピンボール盤面のボールだけは物理半径と見た目の直径を一致させるため、`size={BALL_RADIUS * 2}`を明示します。

## 座標系とエリアデータ構造

1エリアの論理座標は幅480×高さ720です。端末の幅・高さは物理値やコースデータへ持ち込まず、`useAreaScale`のCSS transformだけで表示へ反映します。各エリアはローカル座標（0..480, 0..720）でオーサリングし、ワールド座標上の`origin`を明示します。

Phase 1のoriginは次の縦積みです。

| エリア | id | origin |
| --- | --- | --- |
| そら | `sky` | `{ x: 0, y: 0 }` |
| もり | `forest` | `{ x: 0, y: 720 }` |
| どうくつ | `cave` | `{ x: 0, y: 1440 }` |
| ゴール | `goal` | `{ x: 0, y: 2160 }` |

`AdventureArea`は`id`、子ども向けの`nameJa`、`theme`、`origin`、`objects`、`exits`を持ちます。壁とピンはローカル座標の静的オブジェクト、出口はセンサー矩形です。出口はPhase 1では各エリア1個ですが配列で持ち、`to: null`をゴールとして扱います。左右の外壁は面白さを表すデータへ混ぜず、物理世界の構築時に全エリアへ自動生成します。上壁はスタートだけ、最終ゴールの床はゴールエリアのデータだけに置きます。

入口へボールを置く`AREA_ENTRY_CLEARANCE=60`の範囲には障害物を置きません。物理データテストでは、id重複、出口参照、スタートからの到達性、ゴール出口、矩形内への収まり、入口余白、障害物間の「ボール直径＋16px」以上の最小余白を確認します。

## カメラ方式

物理世界は1つで、4エリアの静的ボディと1個のボールを最初にまとめて生成します。DOMは次の入れ子です。

```text
.fit（absolute inset:0、計測対象）
└─ .stage（実px）
   └─ .viewport（480×720、overflow:hidden、scale）
      └─ .world（全エリアをoriginのworld座標で配置、translate(-camX,-camY)）
```

カメラは現在エリア内では固定し、ボールを追従してスクロールさせません。出口センサーに触れたときだけ、現在エリアのoriginから次エリアのoriginへ`CAMERA_TRANSITION_MS=600`msで`easeInOutCubic`補間します。移動中は`Engine.update`を呼ばず、ボールの速度を保持したまま次エリアの入口へ置きます。移動完了後は`CAMERA_SETTLE_MS=120`ms待ち、視線が着地してから物理を再開します。

`useAreaScale`は既存の`useBoardScale`と同じく幅・高さから求めた倍率の小さい方を採用し、上限1.6倍、ResizeObserver未対応時はresizeイベントへフォールバックします。カメラのoffsetを含むworldを扱う責務はピンボールと将来変わりうるため、`useBoardScale`は変更せず新ゲーム側へ別Hookを置きます。

## 物理パラメータ

調整しやすいよう、テンポと物理値は`adventurePhysics.ts`へ集約します。ピンボールの速く跳ねる手触りと分け、ゆっくり転がって眺められる初期値にします。

| 定数 | Phase 1値 | 意図 |
| --- | ---: | --- |
| `STEP_MS` | `1000 / 60` | 端末差を抑える固定タイムステップ |
| `GRAVITY` | `{ x: 0, y: 0.35 }` | ピンボールの0.55より弱く、見守る時間を作る |
| `START` | `x=240, jitterX=40, vx=-1.2..1.2, vy=0..1.2` | 毎回同じ映像にならないよう、入口を塞がない範囲で開始位置と初速を揺らす |
| `BALL_RADIUS` | `22` | 480幅の約9%で国旗を見分けやすくする |
| `BALL_RESTITUTION` | `0.45` | 跳ねすぎず転がる |
| `BALL_FRICTION` | `0.02` | 斜面で止まりすぎない |
| `BALL_FRICTION_AIR` | `0.012` | ゆっくり減速する |
| `BALL_DENSITY` | `0.002` | Matter.jsで扱いやすい密度 |
| `WALL_RESTITUTION` | `0.3` | 壁から強く跳ね返りすぎない |
| `PIN_RESTITUTION` | `0.7` | ピンに触れた反応を少し見せる |
| `MAX_SPEED` | `14` | すり抜けと速すぎを防ぐ |
| `MAX_ANGULAR_VELOCITY` | `0.22` | 国旗が読めないほど回転させない |
| `MAX_FRAME_DELTA_MS` | `100` | タブ復帰時の大きな実時間差分を抑える |
| `MAX_SUBSTEPS` | `5` | 復帰直後の追いつき処理を制限する |
| `CAMERA_TRANSITION_MS` | `600` | エリア移動を見守れる長さにする |
| `CAMERA_SETTLE_MS` | `120` | カメラ停止後の視線の着地を待つ |
| `AREA_ENTRY_CLEARANCE` | `60` | 入口直後の詰まりを避ける |

スタート時は`playPinballLaunchSound()`、ピン衝突時は`playPinballBumperSound()`、ゴール時は`playPinballTotalSound()`を使います。既存の音関数は意味と音量が合うため再利用し、`quizSound.ts`へ新しい名前や音声素材は追加しません。ピン通知は同一ピン120ms、全体70msのクールダウンを設けます。

## プレイ時間・テンポの測定

`adventureSimulation.ts`は`areas.ts`と`adventurePhysics.ts`を直接共有し、画面サイズ・CSS scale・rAFを参照せず、matter-jsを固定タイムステップでヘッドレス実行します。開始時は`START`の揺らぎをシード付き乱数で再現し、エリア遷移時は物理を止めた`CAMERA_TRANSITION_MS + CAMERA_SETTLE_MS`も経過時間へ加えます。24シードで測定した合計時間は次の通りです。

| 試行数 | min | median | mean | max |
| ---: | ---: | ---: | ---: | ---: |
| 24 | 17.510秒 | 19.202秒 | 19.201秒 | 22.927秒 |

24シード中23種類の合計時間が得られ、開始揺らぎが毎回同じ映像になることを防いでいます。

合計時間には3回分のカメラ遷移・着地待ち（合計2.16秒）を含み、エリア別滞在時間には含めません。エリア別の平均滞在時間は次の通りです。

| エリア | 平均滞在時間 |
| --- | ---: |
| `sky` | 5.742秒 |
| `forest` | 4.018秒 |
| `cave` | 3.861秒 |
| `goal` | 3.420秒 |

skyの斜面角度を`0.22`から`0.36`へ立て、caveの斜面を`0.30`へ調整しました。goalは下側漏斗を左右外壁近くまで延長し、外側ポケットを左右の受け皿で中央センサーへ戻す構造にしています。中央ピンは1つだけ残し、シード間で合計時間が変わることと、通常24試行で`rescueCount=0`、`stallNudgeCount=0`、`areaTimeoutCount=0`になることを`adventureSimulation.test.ts`で検証します。

## 詰まり対策と終了保証

物理軌道は固定値に依存せず、次の順番で救済します。

1. 速さが`0.35`未満の状態が`1200ms`続いたら、横`1.8px/step`と少し上向きの速度を`Body.setVelocity`で直接与えます。`Body.applyForce`はMatter.js内部でdeltaの二乗が掛かり、軽い押しが過大になりやすいため使いません。向きだけランダムにして、頻繁なワープにしません。
2. 同じエリアに`12000ms`留まったら、そのエリアの最初の出口へ到達したものとして扱います。次エリアの上端中央へ移し、速度と角速度をリセットしてカメラ移動を開始します。最終ゴールエリアで発動した場合はゴール通知へ進みます。
3. 現在エリアの左右から80px以上、上から200px以上、または下端から200px以上外れた場合は救済します。左右・上方向は現在エリアの上端中央へ戻し、下方向はそのエリアの出口へ進めます。出口が`to: null`なら、ゴールエリアの中央センサーを取りこぼしていても即時にゴール通知します。下方向も見るのは、goalの出口だけが中央120pxで、漏斗の外側に床のないポケットがあるためです。
4. 毎ステップで速度と角速度をクランプします。

範囲外救済では`areaEnteredAt`を更新しません。エリアのタイムアウト時計はエリア遷移時だけ始め直し、救済が繰り返されても同じエリアに無限に留まれないようにします。

これらをエンジン側の状態機械とエリアタイムアウトで持つことで、偶然の物理軌道に関係なくゲームがゴールまで終了する構造を保証します。

## 背景とコースの見た目

`AreaBackground`は1枚絵にせず、下から`layerBase`（背景色・グラデーション）、`layerFar`（山・雲・岩のCSS図形）、`layerDecor`（背景装飾）の3レイヤーを持ちます。前景用の`AreaForeground`は`.world`内でボール要素より後ろ（z-indexは上）にエリアごとに置き、Phase 1では空のレイヤーだけを用意します。z-indexの意味と順序は`layerOrder.ts`に集約し、背景3層 → コース → ボール → 前景の順で重ねます。Phase 1のテーマはsky／forest／cave／goalのCSS Modulesクラスで色を切り替え、4エリアの雰囲気が一目で分かる程度の図形に留めます。背景アニメーションは入れていないため、`prefers-reduced-motion`でも動きが増えません。

コースの壁とピンもエリアthemeを親クラスから受け、そらは雲色、もりはキノコ色、どうくつは岩色、ゴールは明るい金色で描き分けます。衝突時のピン発光は短いCSSクラスだけで、紙吹雪や大きな演出は入れません。

## レスポンシブ

スマートフォン縦画面とタブレット縦画面を主対象にします。プレイ画面は固定の「やめる」を盤面から離し、高さ48pxのヘッダ以外をstageへ渡します。論理画面全体を小さくしてでも1エリアを見切らないよう、scaleに下限は設けません。320px幅でも選択画面のグリッドとsticky操作バーが画面外へ隠れず、ゴール画面も3つの操作を縦に並べます。PCでは上限1.6倍を設け、横長画面でも論理エリアの全体を表示します。

## テスト

`FlagRollAdventure.test.tsx`では`useAdventureEngine`をmockし、40個の選択、1個だけの置換、state遷移、エリア名通知、800ms後のゴール、再挑戦・別国旗・終了・不正URLを検証します。fake timersはゴール待ちの関数内だけで有効にし、userEventを使う前にreal timersへ戻します。

`adventureState.ts`、`camera.ts`、`playState.ts`は物理から分離した純粋関数として単体テストします。エリアデータテストでは、物理軌道を固定せず、エリアの接続・矩形内・入口余白・障害物間隔を検証します。`adventureSimulation.test.ts`では座標を固定せず、複数シードのゴール到達・時間レンジ・シード間の時間差・通常時のタイムアウトなしを検証します。`useAdventureEngine`の固定値軌道はテスト対象にせず、固定タイムステップ・直接DOM transform・cleanupは実装レビューと型チェックで確認します。

## 今後のフェーズ

- **Phase 2：分岐** — `AreaExit[]`へ出口と次エリアをデータ追加し、左下・右下・横方向のorigin配置と選択結果を実装する。Phase 1では1本の縦経路だけに限定する。
- **Phase 3：ギミック** — 大砲、可動壁、スイッチ、逆重力などを追加する。ただし操作の有無と安全な詰まり対策を先に設計し、Phase 1の見守り体験を壊さない。
- **Phase 4：世界観と素材** — 背景レイヤーごとに権利を確認した本番素材を追加し、CSS仮背景から差し替える。画像を1枚絵へ集約せず、レイヤーの責務を保つ。
- **Phase 5：調整** — 実機でエリア滞在時間を測り、斜面角度・ピン配置・カメラ移動・音の間隔を調整する。得点やランキングを追加するフェーズではない。
