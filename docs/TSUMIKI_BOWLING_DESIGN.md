# つみきボウリング 設計（Phase 1）

対象Issue: [#469](https://github.com/KoheiKasahara/kids-playground/issues/469)

## 1. どんなあそびか

未就学児向けの、正誤判定のない3D物理アクショントイです。
玉を指でひっぱって離すと、スリングショットのように飛び出し、
奥に積んだ積み木のタワーへ突っ込んで崩します。1プレイ3投で、
倒した積み木の数を数えます。失敗はありません。

Phase 1 でもっとも重要な要件は、物理的な正しさでも本物のボウリングらしさでもなく、

> 「ビューン！」→「ドカン！」→「ガラガラ！」

が画面から伝わることです。玉がゆっくり転がる・当たっても少ししか動かない、
といった既存3D物理ゲームで見られた地味さは、設計段階から避けています。

- URL: `/games/tsumiki-bowling`
- カテゴリ: 3D
- カメラ: 固定（プレイヤーは操作しない）
- 玉: 「どっしりだま」1種類のみ（Phase 2で3種類へ）
- ステージ: 固定1種類（Phase 3で複数へ）

## 2. ファイル構成と責務

```text
src/games/tsumiki-bowling/
├─ bowlingPhysics.ts          物理パラメータの一元管理（重力・摩擦・発射速度など）
├─ bowlingBalls.ts            玉の定義（Phase 2の追加はここへ1件足す）
├─ bowlingStage.ts            レーンの形と積み木の配置データ（Phase 3の追加はここへ1件足す）
├─ bowlingLaunch.ts           ドラッグ → パワー・方向・予測軌道（純粋関数）
├─ bowlingTopple.ts           倒れ判定（純粋関数）
├─ bowlingSettle.ts           1投の終わり判定（純粋関数）
├─ bowlingGame.ts             3投の進行（純粋関数）
├─ bowlingCamera.ts           固定カメラの位置と画角（純粋関数）
├─ bowlingWorld.ts            Rapierの世界（Three.js非依存。headlessテスト可能）
├─ useTsumikiBowlingEngine.ts Three.js + Rapier + 入力（useEffectの中だけで動く）
└─ TsumikiBowlingPlay.tsx     画面とHUD（毎フレームのReact再描画はしない）
```

分離の方針は既存の3Dゲーム（`flag-roll-maze` / `koma-battle`）と同じで、
**物理と見た目を分け、物理側はThree.jsにもDOMにも依存させない**ことです。
これにより「最大パワーで積み木をすり抜けないか」「本当に崩れるか」を
vitestの中で実際にRapierを回して確認できます。

数値はコンポーネントに直書きせず、必ず `bowlingPhysics.ts` /
`bowlingBalls.ts` / `bowlingStage.ts` から読みます。
一方で、将来だけを見込んだ抽象化（プラグイン機構、ステージDSLなど）は作りません。

## 3. 座標系とレーン

- `+X` 画面右 / `-Z` 積み木のある奥 / `+Z` 発射位置のある手前
- レーン面の高さは `laneSurfaceY(z) = z * tan(LANE_SLOPE_RAD)`
- `LANE_SLOPE_RAD = 0.055`（約3.1度）のごく緩い下り勾配

勾配は「坂で加速させる」ためではなく、発射時の初速を失いにくくするための保険です。
勢いそのものは発射速度（`LAUNCH_SPEED_MIN/MAX`）が決めています。
これ以上急にすると、置いただけの積み木が自重で滑り始めます。

積み木は勾配に沿った姿勢（`laneTiltQuaternion()`）で置くので、
配置データ側は勾配を意識せずに「レーン面からの高さ」で書けます。

## 4. スリングショット操作

- 画面のどこをドラッグしても構わない（小さな玉を正確に掴む必要はない）
- **ドラッグ距離 → パワー**（画面の短辺の45%で最大。上下限110〜320px）
- **ドラッグ方向 → 発射方向**（引いた向きの逆へ飛ぶ）
- 左右は `LAUNCH_YAW_LIMIT_RAD = 0.17`（約9.7度）に制限
- 上（奥）へ押しても後ろへは飛ばず、必ず前方へ出る
- 12px未満のドラッグは「画面に触れただけ」として発射しない

ガイドは**予測軌道の点の並び**と着地点の輪で見せます。
当初は玉から前方へ伸びる矢印にしていましたが、カメラが発射方向のほぼ真後ろにあるため
奥行き方向に潰れてまったく見えず、実画面確認で作り直しました。
点の長さがそのままパワー、左右の曲がりが発射方向になり、文字を読めなくても分かります。
色も黄→赤へ変化し、HUDには「よわい / ふつう / つよい！」を出します。

### 入力の受け付け範囲

幼児は積み木が止まる前に次を触ります。そこでドラッグの受け付けは
**前の投球が転がっている最中でも開始できる**ようにし、実際に発射してよいかは
指を離した時点で判定します。組み直し待ちの最中に離した場合は、
待ち時間を飛ばしてその場で組み直してから発射します。
（この対応前は、待ちきれずに触った投球が丸ごと空振りになっていました）

## 5. 発射位置と「勢い」の設計

| 値 | 設定 | 理由 |
|---|---|---|
| 発射高さ | レーン面から 2.9m | 積み木の最上段（約2.73m）より高い位置から斜め下へ打ち込む |
| 発射位置Z | +7（積み木まで約13.2m） | 最大パワーで到達まで約0.4秒、最小パワーで約0.8秒 |
| 伏せ角 | 0.075rad（約4.3度） | 水平に撃つと塔の上を越えてしまう。助走を伸ばしたぶん落下量が増えるので、着弾高さが変わらないようわずかに寝かせている |
| 発射速度 | 16〜33 m/s | 最小でも「コロコロ」にならない速さを下限にする |
| 重力 | -16 | 崩れた積み木がふわふわ落ちないよう実寸より強く |
| 玉の減衰 | linear 0.012 / angular 0.05 | 発射後に不自然に失速させない |
| 玉の質量 | 約4.9kg（半径0.46・密度12） | 積み木1個（約0.20kg）の約25倍。当たっても玉が減速しない |
| 玉の反発 | 0.08 | 跳ね返らずに押し切って直線的に進む |

### 玉と積み木の距離感

「ひっぱって離す → ビューンと進む → 少し進んでから衝突する」の流れが
成り立つよう、玉から最前面の積み木までの助走距離を 11.0m → 13.2m（約20%増）に
広げています。実測の到達時間は最大パワーで 0.32秒 → 0.39秒、
最小パワーで 0.67秒 → 0.80秒です。

距離は塔の位置（`bowlingStage.ts` の `TOWER_DEPTH_OFFSET`）だけで調整し、
発射速度・パワーには手を付けません。「離した瞬間の速さ」がこのゲームの
気持ちよさそのものなので、距離の都合で勢いを削らないためです。

カメラは、塔が遠くなったぶんだけ画角を詰めて拡大し返さないようにしています
（`REQUIRED_HALF_WIDTH`）。拡大し返すと手前の玉が画面の外側へ押し出され、
下端の操作パネルへ潜り込みます（実画面で確認）。結果として、
玉の見え方は変更前と同じまま、塔だけが少し小さく＝少し遠くに見える構図になります。

発射時には転がりぶんの角速度も同時に与えています。これがないと着地の瞬間に
摩擦で回転を作るための減速が起き、勢いが落ちて見えます。

「重いから遅い」という調整はしていません。重くて速い玉です。

## 6. 高速衝突（すり抜け対策）

最大33m/sという速度を、速度を下げずに成立させるための設定です。

- 物理タイムステップ **1/180秒**（1ステップの移動距離が約0.18m。積み木の最小厚み0.3mより十分小さい）
- 玉・積み木の両方で **CCD有効**
- 玉はさらに **soft CCD**（`setSoftCcdPrediction(半径×2)`）を併用
- ソルバ反復回数を8（既定4）へ。20個積んだ塔が初期状態で沈み込まないようにする
- 速度の安全弁（玉40 / 積み木26 m/s、角速度90 rad/s）は「暴走を止めるため」であって、遅くするためではない

`bowlingWorld.test.ts` で、最大パワーの投球が
「必ず減速する（＝すり抜けていない）」「塔の半分以上を崩す」ことを実際に回して確認しています。

## 7. ステージ「つみきタワー」

固定1ステージ、20個の積み木です。1発当てるだけで大きく崩れるよう、
次の順に力が伝わる形にしています。

1. 壁の上のキューブ2個が弾け飛び、「当たった！」が分かる
2. **幅いっぱいの横長の壁（4.2m）** が倒れ込み、後ろの柱をまとめて倒す
3. 柱が抜けた板が落ち、その上の柱・長い板・てっぺんのキューブが続けて落ちる
4. 柱は前後2列あるので、手前の崩れが奥へも伝わる

配置を決めるときに実測で分かった、外せない条件が3つあります。

- **同じ段の積み木を絶対に重ねない**。少しでも重なっているとRapierが開始直後に弾き飛ばし、
  何もしていないのに塔が崩れる（実際に19個中5個が勝手に倒れた）。
- **横に並ぶ積み木のすき間を玉の直径より狭くする**。広いと弾道の低い弱い発射が
  間をすり抜けて、当てたつもりなのに1個も倒れない投球になる（実際に0個の投球が出た）。
- **幅いっぱいの壁を手前に置く**。これがないと、まん中へ当てても左右の山が立ったままで、
  20個中6個しか倒れない寂しい崩れ方になる。

これらは `bowlingStage.test.ts` で機械的に検査しているので、
Phase 3 でステージを足すときも同じ品質を保てます。

## 8. 倒れ判定

単純な接触では、かすっただけ・隣が揺れただけでも数えてしまい、
画面の見た目と数字が食い違います。次のいずれかが**220ms続いたとき**に確定させます。

- 初期姿勢から **0.5rad（約29度）以上** 傾いた
- 初期位置から水平に **0.42m以上** 動いた
- 初期位置から **0.35m以上** 落ちた

確定した積み木はラッチして戻さないので、揺れて条件を出入りしても二重には数えません。
判定の基準姿勢は**投球ごとに取り直す**ため、組み直し直後のごくわずかな沈み込みは数えません。

## 9. 1投の終わりと3投の進行

固定秒数だけに頼らず、剛体の速度を見て判断します。

- 全体が「並進0.45m/s以下 かつ 角速度1.5rad/s以下」の状態が **520ms続いたら終了**
- ただし発射から **900msは必ず待つ**（玉が積み木へ届く前に終わらせない）
- 何かが転がり続けても **7秒で打ち切る**
- レーン外へ落ちたものは落下し続けるので、判定から除外する

1投終わると **700ms** 崩れた形を見せてから積み木を組み直します。
組み直しはBodyを作り直さず、位置・姿勢・速度・力を初期値へ書き戻します。

**各投のはじめに積み木を組み直す**のはこのゲームの決まりです。
1投目で全部倒れても2投目・3投目がつまらなくならないようにするためで、
合計は「3回ぶんの倒した数の和」になります。

「もういちど」は `runId` を増やして世界ごと作り直すので、
前のプレイの物理状態は一切残りません。

## 10. カメラ

固定カメラです。位置 `(0, 8.4, 14.2)`、注視点 `(0, -0.2, -4.6)`。

発射位置は積み木より高いので、カメラを低くすると手前の玉が画面中央で積み木に重なり、
塔がまったく見えなくなります（実画面で確認）。はっきり見下ろすことで、
画面の下側に玉・上側に積み木という構図になります。

画角は画面比から決めます。縦画面ほど横方向が狭くなるので、
塔の幅が収まるところまで画角を広げ、横長画面では縦に必要な最小画角（30度）まで絞ります。
これにより横長画面でも必要以上に引かず、大きく見えます。
`bowlingCamera.test.ts` で、代表的な画面比すべてについて
「玉と積み木の上端が画角の内側に入る」ことを検査しています。

演出として、強い衝突のときだけ短いカメラの揺れと光の輪を出します
（`prefers-reduced-motion` では揺れません）。

## 11. UI / UX

- スマホ縦画面を優先。主操作はcanvas上のドラッグなので、狭い画面でも操作領域が広い
- 上部に投球数（●○○）と「たおした つみき ◯こ」
- 倒した数は**崩れている最中も増えていく**（崩れているのに0のままだと手応えが伝わらない）
- ドラッグ中はパワーのバーと「よわい / ふつう / つよい！」
- 3投後に合計と「もういちど」（`--tap-target-min` 以上の大きさ）
- 数え上げは `role="status"` / `aria-live="polite"` で読み上げる
- 正誤・失敗の表現は作らない。0個でも「つぎは あたるかな？」

## 13. Phase 2 以降への拡張

- **Phase 2（玉3種類）**: `bowlingBalls.ts` の `BOWLING_BALL_SPECS` へ2件足し、
  選択UIから `ballId` を渡す。玉ごとに変わる値（大きさ・質量・反発・減衰・発射速度倍率）は

  全ステージへ広げる。

## 14. Phase 4（演出・効果音・UX仕上げ）

対象Issue: [#472](https://github.com/KoheiKasahara/kids-playground/issues/472)

物理パラメータ（`bowlingPhysics.ts` / `bowlingBalls.ts` の物理項目 / `bowlingStage.ts` の配置 /
`bowlingWorld.ts` の Collider・CCD・ソルバ設定）は一切変更していない。足したのは
視覚・音・触覚・UIのフィードバック層だけである。

### 新規モジュール

- `bowlingFeedback.ts`: 玉の運動と倒壊数から「衝突」「バウンド」「大崩壊」の演出イベントを
  作る純粋関数。旧 `useTsumikiBowlingEngine.ts` にあった `IMPACT_SPEED_DROP` 一本槍の判定を
  ここへ移し、バウンド検出（下向き→上向きの速度反転）と、短時間にまとめて倒れたかの
  時間窓判定を足した。Three.js/Rapier/DOM非依存で、時間経過も `Date.now()` ではなく
  引数の `stepMs` 積算だけで扱うため、vitestでフレーム差分をそのまま検証できる。
- `bowlingSound.ts`: 「何を鳴らすか」（`launchTones` 等の純粋関数）と「実際に鳴らす」
  （`createBowlingSoundController`）を分離。共有 AudioContext は `quizSound.ts` の
  `getSharedAudioContext()`（Phase 4で追加）を使い、iOSで複数Contextを作らない。
- `bowlingHaptics.ts`: `navigator.vibrate` を使った軽い振動。対応チェック＋try/catchで
  必ず失敗を吸収し、非対応端末でもゲームは完全に成立する。

### 発射・衝突・崩壊演出の方針

- 発射ガイドはパワーに応じて点を太くし、最大付近（0.85以上）ではゆっくり脈動＋強い赤へ張り付く。
  `prefers-reduced-motion` では脈動しない。
- 発射直後、玉の一瞬の伸び（`LAUNCH_POP_MS`）・発射位置のフラッシュ・玉ごとの残像トレイルを追加。
  トレイル・衝撃リング・きらめきパーティクル（`THREE.Points`を1つだけ使い回す）は、すべて
  初期化時に確保したプール/配列を使い回し、毎フレームの新規オブジェクト生成をしていない。
- 衝突エフェクトは強さ（strength、0〜1）でリングの大きさ・不透明度・カメラ揺れを変える。
  弱い衝突（strength < 0.25）ではカメラを揺らさない。
- 「大崩壊」（`BIG_COLLAPSE_COUNT`=5個が`BIG_COLLAPSE_WINDOW_MS`=450ms以内に倒れた）では、
  大きめのきらめき・やや強めのカメラ揺れ・「ガラガラー！」の短いチップ（900ms）を出す。

### 玉ごとの演出差

演出専用のテーブル `BALL_VISUALS`（`useTsumikiBowlingEngine.ts` 内）と、`bowlingSound.ts` の
玉ごとの音色分岐で、物理パラメータとは別に「見え方・聞こえ方」の差を作っている。

| 玉 | トレイル | 固有の演出 | 音の主な特徴 |
|---|---|---|---|
| どっしりだま | 短く太い | — | 低い「ドン/ゴン」 |
| はずむだま | 中程度 | バウンドごとに地面へ小さなリング | バウンドのたびにペンタトニックで音程が上がる（5段で頭打ち） |
| ちいさいだま | 長く濃い | — | 「シュッ」と駆け上がる短音 |

### 衝突音の多重再生対策（「ガガガガ」対策）

積み木が一斉に崩れると、衝突・バウンド・カラカラ音が同一フレームに何十件も発生しうる。
`createBowlingSoundGate`（`bowlingSound.ts`）が二段構えで間引く。

1. 種類ごとのクールダウン（`BOWLING_SOUND_COOLDOWN_MS`: launch 120 / impact 90 / bounce 110 /
   clatter 70 / perfect・result 600 ms）
2. 直近200msに鳴らした音の合計数が `MAX_ACTIVE_BOWLING_VOICES`(6) を超えたら拒否

`perfect` / `result` はクールダウンだけ効かせ、音数上限の対象から外している
（積み木の崩壊音でお祝いの音が潰れないようにするため）。`clatterTones` 自体も、
何十個倒れても音は最大2音までしか重ねない。

### パーフェクトの定義

「3投のうち1回でも、その投球で全ての積み木を倒したら（`toppled >= total`）パーフェクト」。
`ThrowSettledResult` に `total`（そのステージの積み木総数）と `isPerfect` を追加した。
お祝い（`playPerfect` / `haptics.perfect()`）は結果画面まで待たず、その投球が
落ち着いた直後に鳴らす。結果画面には、3投のうち1回でもパーフェクトがあれば
「パーフェクト！」と紙吹雪・キラキラを一番上に出す（演出は1.2秒ほどで落ち着き、
ボタン操作をいつでも受け付ける）。

### 振動の扱い

`navigator.vibrate` に対応している端末だけ、発射・強い衝突（strength ≥ 0.5）・パーフェクトで
短く振動する。非対応環境・例外・`prefers-reduced-motion: reduce` では常に何もしない
（必須機能ではなく、手触りの上乗せという位置づけ）。

### パフォーマンス方針

- トレイル・バウンドリング・衝撃リング・きらめきパーティクルは、すべて `useEffect` の中で
  一度だけ確保するプール/配列を使い回す。投球中や崩壊時に新しい `THREE.Mesh` /
  `THREE.BufferGeometry` を作らない。
- 音・振動のコントローラ（`createBowlingSoundController` / `createBowlingHaptics`）も
  runにつき1つだけ作り、予約したAudioNodeは `koma-battle`（`quizSound.ts`）と同じく
  Setで追跡して `onended` でdisconnectし、`release()` で必ず `dispose()` する。

### 実画面確認で直した点

数値だけでは分からず、実際に縦画面（390x844 / 320x568）で遊んで初めて分かった不具合。

- **きらめきが一度も見えなかった**: Three.jsは `geometry.boundingSphere` を最初の描画で
  一度だけ計算してキャッシュし、position属性を `needsUpdate` しても作り直さない。
  粒子の初期位置（画面外の y=-1000）から作られた球が残り続け、実際に光っている粒子ごと
  視錐台カリングされていた。`sparklePoints.frustumCulled = false` で解決。
- **衝撃リングが塔を覆っていた**: 不透明度が「0.85 × 強さ係数」で1に張り付き、広がった
  リングが崩れる様子を隠していた。上限0.8を設け、広がる大きさも抑えた
  （「気持ちよさは足すが、物理の見やすさは削らない」）。
- **「ガラガラー！」が玉選択カードと重なっていた**: 画面下寄り（`bottom: 16%`）へ移した。
  このチップが出る飛行中〜落ち着くまでは下端のねらい案内が消えているため、下側は空いている。
- **背の低い画面でゲームが画面外にあった**: ステージ選択→プレイはURL遷移ではないため
  `app/ScrollManager.tsx` の「遷移したら先頭へ」が効かず、一覧を下までスクロールして
  選ぶと説明文が表示されたままだった。`TsumikiBowlingPlay` で切り替えのたびに先頭へ戻す。
- **背の低い画面で玉選択カードが塔の天辺を隠していた**: `max-height: 680px` でカードを
  一回り小さくする（縮めてもタップ領域は約70pxあり、幼児向けの下限56pxを下回らない）。
  そのためカード内の玉の大きさは、インラインstyleではなくCSS変数 `--ball-orb-size` で渡している。
