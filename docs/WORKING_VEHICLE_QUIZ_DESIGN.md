# 「はたらくくるまクイズ」基本設計

## 1. 目的と対象

身近な仕事や工事を支える車両を、実写写真と子ども向けの名前で楽しく覚える4択クイズです。
主な対象はスマートフォンやタブレットを使う子どもで、文字がまだ得意でない利用者にも写真と大きな操作領域で参加しやすくします。

バックエンドや外部APIは使わず、問題データと写真をすべてアプリへ同梱します。

## 2. ゲームモード

| 内部名 | 表示 | 問題 | 選択肢 |
| --- | --- | --- | --- |
| `photoToName` | しゃしん → なまえ | 車両写真 | 車両名4件 |
| `nameToPhoto` | なまえ → しゃしん | 車両名 | 車両写真4件 |

両モードとも1ゲーム10問です。正解問題はゲーム内で重複せず、選択肢は重複なしの4件で正解を1件だけ含みます。

## 3. 画面とURL

| 画面 | URL |
| --- | --- |
| 開始・モード選択 | `/games/working-vehicle-quiz` |
| 写真→名前 むずかしさ選択 | `/games/working-vehicle-quiz/photo-to-name` |
| 写真→名前 プレイ | `/games/working-vehicle-quiz/photo-to-name/:level/play` |
| 写真→名前 結果 | `/games/working-vehicle-quiz/photo-to-name/:level/result` |
| 名前→写真 むずかしさ選択 | `/games/working-vehicle-quiz/name-to-photo` |
| 名前→写真 プレイ | `/games/working-vehicle-quiz/name-to-photo/:level/play` |
| 名前→写真 結果 | `/games/working-vehicle-quiz/name-to-photo/:level/result` |

`:level` は `easy` / `normal` / `hard` です。不正値は同じモードのむずかしさ選択へ戻します。
結果URLは遷移stateがない直接アクセスでは復元できないため、開始画面へ戻します。

画面遷移は次のとおりです。

```text
ホーム → 開始 → モード別むずかしさ → 10問プレイ → 結果
                    ↑                         │
                    └──── べつのむずかしさ ──┘
```

## 4. 画面仕様

### 4.1 開始

- タイトル、10問であること、2つのモード、ホームへ戻る操作を表示する。
- モードは写真・検索を連想する絵文字と平易な文で示す。

### 4.2 むずかしさ選択

- 選択中のモードを表示する。
- かんたん / ふつう / むずかしいを星、ラベル、対象種類数で示す。
- 選択後は該当モード・むずかしさのプレイURLへ移動する。

### 4.3 プレイ

- 現在のむずかしさ、`現在 / 10`、進捗バー、「やめる」を表示する。
- 写真→名前は主写真を大きく表示し、その下に名前4択を置く。
- 名前→写真は車両名を表示し、写真4択を2列×2行で置く。
- 回答後は全選択肢を無効化し、正解を緑枠と`◯`、選んだ誤答を赤枠と`✕`で示す。
- 画面下の固定領域に正誤、正しい名前、次の操作を表示する。
- 最終問の次操作は「けっかを みる」に変える。

### 4.4 結果

- モード、むずかしさ、正解数、成績に応じた短いメッセージを表示する。
- 同条件で再挑戦、別のむずかしさ、別モード、ホームへの4経路を用意する。

## 6. 出題と結果判定

共通の `generateQuizQuestions<T extends { id: string }>` を利用します。

1. 対象レベル以下の車両を抽出する。
2. Fisher–Yatesで並べ替え、正解10件を重複なく取る。
3. 各正解以外から誤答3件を重複なく取る。
4. 正解1件と誤答3件を再度並べ替える。
5. 回答直後に正解数を更新し、10問後に結果stateを渡す。

結果メッセージは10/10、7以上、4以上、それ未満の4段階です。履歴保存や個別車両の学習記録は今回の範囲外です。

## 7. 写真仕様と権利

- `public/vehicles/<id>.webp` として24枚をローカル同梱する。
- Wikimedia Commons上でPublic Domain、CC0、CC BY、CC BY-SAなどの再配布可能な写真だけを使う。
- 配布元ページ、作者、ライセンスは `docs/CREDITS.md` に素材単位で記録する。
- 配布用は車体の切れを避ける中央トリミングまたは余白調整、800×600pxへの縮小、WebP変換、EXIF除去を行う。
- 識別に不要な企業名・電話番号・ナンバーは、必要に応じて判読できないよう部分加工する。
- 車両が主題として識別でき、透かし、人物の顔、判読可能なナンバー、大きな企業広告が主題でないことを確認する。
- 外部ホットリンクは使用しない。

## 8. PWA

- Workboxのprecache対象へ `webp` / `jpg` / `jpeg` を含める。
- 24枚の写真を含めてオフラインで全問題を遊べるようにする。
- 写真はWorkboxの既定上限を超えないよう個別圧縮し、上限値は引き上げない。
- `import.meta.env.BASE_URL` を使い、通常配信とGitHub Pagesの両base pathへ対応する。

## 9. アクセシビリティとレスポンシブ

- 選択肢とナビゲーションはネイティブ`button`を使い、タッチとキーボードに対応する。
- 写真選択肢は答えを読み上げで漏らさず、「1ばんめ の くるまの しゃしん」のように位置で識別する。
- 問題の主写真には「もんだいの くるまの しゃしん」、回答後の正解写真には車名を含む代替テキストを付ける。
- 回答結果は`role="status"`で通知し、色に加えて記号と文を使う。
- 320px級の狭い画面では余白と文字を調整し、低い横画面では問題と選択肢を横配置する。
- 名前→写真の低い横画面は写真4択を4列×1行にする。
- OSのモーション低減設定はグローバルCSSで尊重する。

## 10. テストと受け入れ条件

- 24件、ID・名前・写真パスの一意性、写真実在。
- レベル別12 / 18 / 24件と累積包含関係。
- 各レベルで10問、4択、正解1件、問題・選択肢重複なし。
- 開始、モード選択、むずかしさ、両モードの回答と10問進行、結果、再挑戦。
- 不正levelとstateなし結果URLの安全な戻り。
- ホームカードと主要ルート。
- 24写真のデコード、800×600、WebP、容量、目視による識別性。
- 既存国旗クイズを含む`lint`、全テスト、通常ビルド、Pagesビルドの成功。
