# ぷかぷかレスキュー 設計（Phase 1 / #514）

## 目的・対象年齢

4〜5歳が説明なしで「みずを ふやす → アヒルが うかんで あがる → みずを へらす → アヒルが おりる → ゴール」という因果関係を、見ただけで理解できることを目的にしたゲームです。

Phase 1（このドキュメントの範囲）では、後続のギミック（#515 じゃぐち / #516 せん・排水 / #517 ゲート / #518 ほかの浮遊物 / #519 板・坂 / #520 水車 / #521 複数ステージ / #522 仕上げ）を載せられる土台を作り、その土台のうえで「水位が変わる → 浮遊物が上下する → ゴールへ運べる」という1本の遊びだけを成立させます。

## URLと画面遷移

むずかしさ選択も結果画面も持たず、単一URLで完結します。

| 画面 | URL |
| --- | --- |
| プレイ（唯一の画面） | `/games/pukupuka-rescue` |

```text
ホーム → ぷかぷかレスキュー（みずを ふやす／へらす・やりなおし）→ もどる → ホーム
```

SVGと自前の軽い水位計算だけで動き、物理エンジン・3Dのような重い依存を持たないため、ブロックパズルやうごくぬりえと同じく遅延読込（`React.lazy`）にはせず `routes.tsx` へ静的importで登録しています。

## 技術選定（なぜ物理エンジンを入れないか）

このリポジトリには matter-js（2D物理）と Rapier（3D物理）がすでにありますが、Phase 1では**どちらも使いません**。

- 必要なのは「水位」と「1体の浮遊物の上下」だけで、剛体同士の衝突・摩擦・回転を必要としない。
- 流体（SPH等）は非目標であり、粒子を物理演算すると幼児向けの低スペック端末で安定しない。
- 物理エンジンを入れると、水位という**ゲーム側の単純な状態**が物理結果の副産物になり、ゲート・排水など後続の「水量を移す」設計が難しくなる。

そのため、状態は自前の純粋関数（`waterModel.ts` / `floatModel.ts` / `pukupukaGame.ts`）で持ち、描画はSVG（DOM）にしています。SVGにしたのは、Canvasと違ってテストからDOMとして位置を検証でき、拡大・縮小でも輪郭がぼやけないためです。1フレームで描くノードは数十個で、スマホでも軽量に動きます。

## 座標系

ステージ座標は左上原点・**Y下向き**（SVGの `viewBox` と同じ向き）で、`100 × 150`（スマホ縦に合わせた2:3）です。px換算はせず、SVG側の `preserveAspectRatio` で画面サイズへ合わせます。

「上がる」は常に**Yが小さくなる**方向です。

## 水のモデル（水域単位）

画面全体を1枚の水面として固定実装せず、**水域（`WaterBodyDefinition`）ごとに状態を持ちます**。

| 概念 | 実体 |
| --- | --- |
| 水域 | 矩形（`left` / `right` / `floorY` / `ceilingY`）と初期水位を持つ定義 |
| 水量 | `WaterBodyState.volume`（状態の正） |
| 水位 | `volume / 幅` で導出（`waterLevelOf`） |
| 水面Y | `floorY - 水位`（`waterSurfaceY`） |

**状態の正を「水量」にしている理由**は、#516 排水・#517 ゲートで水域間の移動を入れるとき、幅の違う水槽同士でも「移した量を足し引きするだけ」で水が増減しない計算になるためです。

浮遊物は「自分がいる水域」を毎フレーム `findWaterBodyAt(x, y)` で引き、その水域の水面だけを見て浮きます。上下に重なる水域が増えても、落ちていく先の水域が選ばれます。Phase 1のステージは水域1つ（`main`）ですが、水域を1件足せば上段水槽・下段水槽・排水先を表現できます。

水位はタップ・押しっぱなしの指示をいったん `targetVolume` に入れ、`volume` が一定速度で追いつきます。水位が一瞬で跳ねると「水が増えた」ことが目で追えないためです。

### 割り切っていること

- 水そうの中にある固定物（しきり・ゴールの台）の体積は水量計算から無視しています。台の部分は水より前面に描くため、見た目には水が台に入り込んで見えません。
- しきりは当たり判定としては底まで届く四角ですが、見た目には底に小さな通り道を描いています（左右の水位が同じであることの説明であり、アヒル（直径16）が通れない大きさです）。

## 浮遊物のモデル

完全な浮力計算はしません。「水面に対してどれだけ沈んでいるか」（`submergedRatio`: 0〜1）だけを指標に、次の3つを合成しています。

1. **浮力**: `重力 - 重力 × BUOYANCY_RATIO × submergedRatio`。つり合う沈み込みは `1 / BUOYANCY_RATIO`（= 0.4）になります。
2. **減衰**: 水中でだけ強くする。減衰を弱めに残しているため、水位が動いたあと数回ゆれてから落ち着きます（＝ぷかぷか）。
3. **水平の流れ**: 水に触れているあいだだけ、ゴールの向きへ弱く流されます。向きはステージ定義に持たせず、ゴールと開始位置から `stageDriftDirection()` で決めています。

固定物は矩形で、円との最小移動量で押し出します。押し出した向きへ入っていく速度成分だけを消すので、しきりに沿って浮き上がる動きは残ります。最後にステージ外へ出ないよう位置を丸め、床・壁を大きく貫通しません。

見た目の上下ゆれ・回転はCSSアニメーション（`.floaterBob`）で、ゲーム座標には影響しません。`prefers-reduced-motion` で止まります。

## ステージ「はじめの おふろ」

```text
     ┌──────────────┐  ← 満水面 y=30
     │              │
     │      ┃       │  ┃ = しきり（上端 y=66）
     │      ┃   ▁▁▁ │  ▁ = ゴールの台（上面 y=96、浮き輪あり）
     │  🦆  ┃   ███ │
     └──────────────┘  ← 床 y=126
```

遊びの流れは次の3手だけです。

1. **みずをふやす**: 水面が上がり、アヒルが浮いて上がる。
2. 水面がしきりの上端を越えると、アヒルがゆっくり右へ流れて壁を越える。
3. **みずをへらす**: 水面が下がり、アヒルがゴールの浮き輪へ降りてクリア。

「ふやす」だけでも「へらす」だけでもクリアできず、両方の因果を1回ずつ体験できる最小構成です。ゴール領域（`x 56..84 / y 86..96`）は台のすぐ上に広く取ってあり、水を減らし切れば必ず通過するため、水位をぴったり合わせる精度は要求しません。

ゴール判定は `phase` が `playing` のときだけ行い、`cleared` へ移った1ステップだけ `goalReached` が `true` になります。クリア後は何フレーム進めても発火しないため、演出・効果音が連続発火しません。

## Phase 1の水位操作（あとで置き換える前提）

「みずを ふやす」「みずを へらす」の2ボタンだけです。押しっぱなしで連続的に増減し、1タップでも一定量が変わります（キーボードのEnter/Spaceでも1回ぶん動きます）。

この操作は #515 じゃぐち / #516 せん の**仮の入り口**です。入力は `stepGame(stage, state, deltaMs, control)` の `control` と `applyWaterTap()` に集約してあるので、正式ギミックを足すときはステージ定義に部品を追加し、画面側の入力の作り方だけを差し替えれば済みます（水位・浮力・ゴールのロジックは変更不要）。

## 進行と後片付け

- 物理は常に 1/60 秒の固定ステップで進めます。端末のfpsが違っても結果が変わりません。
- 1フレームで進めるステップ数には上限（5）があり、タブ復帰などで巨大な経過時間が来ても暴走しません。
- `requestAnimationFrame` はアンマウント時に `cancelAnimationFrame` で止め、押しっぱなし解除用の `window` イベントも解除します（タイマー・ループの残留なし）。

## UI / アクセシビリティ

- 主要操作（ふやす・へらす）は高さ76pxの2ボタンで、押している間にページがスクロールしないよう `touch-action: none` を指定しています。
- 「もどる」は64px以上、「やりなおし」は48px以上で、主要操作から離した位置に置いています。
- ステージSVGは装飾として `aria-hidden` にし、状態は `role="status"`（`aria-live="polite"`）のテキストが伝えます。読み上げが毎フレーム走らないよう、この文言はクリア時だけ変わります。
- 320px幅の狭い縦画面でも1画面（`100dvh`）に収まり、横スクロールは発生しません。低い横画面ではステージを左、操作を右に置きます。
- 装飾の絵文字はすべて `aria-hidden="true"` です。

- じゃぐち・排水・ゲート・水車の正式実装
- 複数ステージ、ステージエディタ
- 浮遊物ごとの重量・密度差
- 最終品質のSE・エフェクト（#522で仕上げる）
