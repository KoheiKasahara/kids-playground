# 「こっきころころめいろ」基本設計

## 概要とこの文書の範囲

「こっきころころめいろ」は、スマートフォン・タブレット・PCで盤面を傾け、ボールを3D迷路のゴールまで転がすミニゲームです。対象は幼児（4〜5歳を想定）で、正誤やスコアを競うクイズではなく、「盤面を傾けてボールを転がす操作そのものが楽しいか」を確かめるための最小構成です。

この文書はPhase 1（単一ステージ・バーチャルスティック操作・国旗ボールなし）を扱います。ミニゲーム開発規約（`docs/MINIGAME_DEVELOPMENT_GUIDELINES.md`）§9はクイズ系ゲームの設計書を主に想定しており、このゲームはクイズではないため、問題数・選択肢数・むずかしさの累積包含に関する項目は対象外です。かわりに、入力の抽象化、物理構成、詰まらないための仕組みを中心に記載します。

## URLと画面遷移

```text
/games/flag-roll-maze   プレイ（単一画面）
```

`src/app/routes.tsx` に `lazyRoute` で登録し、Three.jsとRapierを含むこの画面は遅延読み込みします。ホームの「こっきころころめいろ」カードから入り、画面下の「もどる」ボタンで `/` へ戻ります。

Phase 1はステージが1つしかなく、クリア後にできることも「もういちど」（同じステージを最初からやり直す）だけなので、ステージ選択画面も結果画面も設けていません。ゴール後の状態は同じプレイ画面の中で `gameState` を切り替えて表現します。

## Phase 1のスコープ

実装したもの:

- バーチャルスティック（ポインタ操作）と矢印キー／WASDによる盤面の傾き操作
- Three.jsによる3D描画とRapier 3D（`@dimforge/rapier3d-compat`）による物理演算
- 蛇行する一本道の迷路ステージ1つ
- 場外からの復帰、停滞検知からの弱いナッジ、いつでも押せる「スタートに もどる」
- ゴール到達時の効果音（`playCorrectSound`）と「もういちど」

あえて入れなかったもの（すべて後続Phaseの対象）:

- スマートフォンのジャイロ（Device Orientation）操作
- 国旗ボール（見た目は単色の球のみ）
- 複数ステージ・ステージ選択画面
- 大砲やジャンプ台のような複雑なギミック
- 派手な演出、効果音以外のBGMやアニメーション

## 入力の抽象化

このゲームの設計の核は、「操作デバイス」と「盤面物理」を`TiltInput`という共通の型で分離していることです。

```ts
// src/games/flag-roll-maze/tiltInput.ts
export type TiltInput = {
  x: number
  y: number
}
```

`x` は盤面のワールド+X方向、`y` は盤面のワールド+Z方向へ「下り坂を作る」量を表します。画面上はカメラが+Z側から見下ろすため、`y`が正だと手前（画面下）へ転がります。大きさ（`x`,`y`のノルム）は常に0〜1に正規化され、1が最大の傾きです。

データの流れは一方向です。

```text
バーチャルスティック / 矢印キー・WASD
        ↓（デバイス固有の値をTiltInputへ変換）
      TiltInput
        ↓ gravityFromTilt()
      重力ベクトル
        ↓ Rapierの world.gravity
       物理演算
```

Phase 2でスマートフォンのジャイロ（Device Orientation）を足すときは、「センサー値 → TiltInput」の変換をもう1つ追加するだけで済み、`mazePhysics.ts` や `mazeWorld.ts` などの物理側は変更不要です。`useMazeEngine`は`setTilt(tilt: TiltInput)`しか受け取らず、入力の出どころ（マウスなのかタッチなのか、将来ジャイロなのか）を知りません。

各責務は次の関数に分かれています。

- デッドゾーン: `applyTiltDeadzone`（`tiltInput.ts`）。しきい値`TILT_DEADZONE = 0.18`の内側を中立にし、境界のすぐ外は0付近から力が立ち上がるよう再スケールする。単純な切り捨てだと境界で急に力が立ち上がるため。
- クランプ: `clampTiltMagnitude`（`tiltInput.ts`）。ノルムが1を超えたら方向を保ったまま1へ丸める。バーチャルスティックの半径超え、キー同時押しの合成の両方で使う。
- 平滑化: `smoothTilt` / `tiltDampFactor`（`tiltInput.ts`）。指数減衰で現在値を目標値へ毎フレーム寄せる。減衰係数は`TILT_SMOOTHING_LAMBDA = 9`（1/秒）で、フレーム落ちしても経過時間から補間係数を再計算するので手触りが変わらない。この処理は`useMazeEngine`の`tick`内で毎フレーム呼ばれ、入力が飛んでも重力が階段状に切り替わらないようにしている。

バーチャルスティックの入力は`tiltFromStickOffset(offsetX, offsetY, radius)`でドラッグ量(px)を`TiltInput`へ変換し、半径を超えて引いても1で頭打ちにします。矢印キー／WASDは`tiltFromPressedKeys`で同時押しを合成してから正規化するため、斜め押しが直線より速くなりません。

## 3D・物理構成

描画にはThree.js（生のAPI）、物理にはRapier 3D（`@dimforge/rapier3d-compat`）を使います。同じRapier wasmは`domino-flag`（こっきドミノ）の`useDominoEngine.ts`と共有しており、新規にwasmを追加していません。

盤面の傾きは、床・壁のコライダーを毎フレーム動かすのではなく、**入力から重力ベクトルの向きを変える**ことで表現します（`mazeWorld.ts`の`applyTiltToGravity`が`world.gravity`を書き換える）。理由は次の2つです。

- 固定コライダーを毎フレーム動かすとRapier側の再計算コストが増え、低速端末で不利になる。
- Phase 2でジャイロ入力を足すときも、`TiltInput`から重力を作る`gravityFromTilt`だけを差し替えればよく、コライダーの姿勢管理を新たに作らずに済む。

重力ベクトルへの変換は次の式です（`mazePhysics.ts`の`gravityFromTilt`）。入力の大きさ`m`（0〜1）から傾き角`θ = m · MAX_TILT_RAD`を求め、大きさが常に`GRAVITY_MAGNITUDE`のまま、水平成分`sinθ`・垂直成分`-cosθ`へ向きだけを変えます。傾けても重力の総量は変わりません。

見た目の盤面（`boardGroup`）は物理と同じ回転軸・向きで、角度だけ`VISUAL_TILT_RATIO = 0.62`倍浅く回します（`visualTiltRotation`）。物理の傾きをそのまま見せると画面の傾きが大きすぎて酔いやすいため、見た目は控えめにしつつ、どちらへ転がしているかは分かる程度の手応えを残しています。

物理は固定タイムステップ`PHYSICS_TIMESTEP = 1/120`秒で積分し、1フレームあたり最大`MAX_PHYSICS_SUBSTEPS = 4`回まで進めます（`useMazeEngine.ts`の`stepPhysics`）。表示は60Hz想定でも、接触判定を薄いコライダーがすり抜けないよう物理は120Hzで刻み、低速端末で追いつけないときは溜まった時間を捨てて次のフレームから作り直します。タブ復帰時などの巨大な時間跳躍は`MAX_FRAME_DELTA_MS = 100`msで頭打ちにしてから物理へ渡します。

床・壁はすべて固定コライダー（親`RigidBody`を持たない`Collider`）で、動的剛体はボール1個だけです。ボールは連続衝突判定（CCD）を有効にし、傾きを止めたままsleepさせない設定にして、次の入力への反応が遅れないようにしています（`mazeWorld.ts`の`createMazeWorld`）。

## カメラ

斜め上から盤面全体を見下ろす固定カメラです（`mazeCamera.ts`）。仰角は`CAMERA_ELEVATION_RAD`（58°）、視野角`CAMERA_FOV`は50°です。`computeMazeCameraSetup`は盤面の四隅（`bounds.minX/maxX/minZ/maxZ`）と壁の高さ（`WALL_HEIGHT`）の8点すべてが画角に収まる最小距離を、水平・垂直それぞれの`tan`から解いて求め、余白係数`CAMERA_MARGIN = 1.1`を掛けます。極端に小さい盤面でもnear面へ入り込まないよう、距離の下限を4に設定しています。この計算はリサイズのたびに`resizeRenderer`から呼ばれ、縦画面でも横画面でも同じ関数で解けます。

見た目の盤面は中心まわりに傾くため、端は上下へ動きます。`visualTiltLift`が最大まで傾けたときの持ち上がり量（盤面の半対角 × `sin(MAX_TILT_RAD · VISUAL_TILT_RATIO)`）を求め、距離を解くときの高さ範囲を`-lift`〜`WALL_HEIGHT + lift`へ広げます。これにより、どの向きへ最大まで傾けても盤面の角が画角から外れません。

カメラは追従しません。ボールを追いかけて動くと、幼児が画面のどこにゴールがあるかを見失いやすいため、盤面全体が常に同じ位置に見える構成にしています。

## 盤面データ

迷路は文字グリッドで持ちます（`mazeStage.ts`）。`#`が壁、`.`が床、`S`がスタート、`G`がゴールです。

```text
#########
#S......#
#######.#
#.......#
#.#######
#.......#
#######.#
#G......#
#########
```

見たままの形を編集できるので、Phase 2以降でステージを増やすときも座標計算をやり直さずに済みます。1マスの一辺は`CELL_SIZE = 1.5`（ワールド単位）で、ボール半径`BALL_RADIUS = 0.42`（直径0.84）に対して十分な通路幅です。

`buildWallRects`は横に連続する壁マスを1枚の矩形へまとめてからコライダーと`Mesh`を作ります。コライダー数・メッシュ数がマス数ではなく壁の「本数」で決まるため、低速端末でも軽くなります。

Phase 1のステージは行き止まりのない一本道の蛇行コースです。すべての床マスが（START/GOAL以外は）2方向以上へ開いており、幼児が分岐で迷って詰まる要素を作っていません。経路探索（`findMazePath`によるBFS）は自動テストの「実際に転がしてゴールへ着けるか」の検証にも使われます。

## 子ども向けの操作感

「難しくするより触っていて気持ちいいこと」を優先し、実測できる数値で手触りを決めています（`mazePhysics.ts`）。

| 項目 | 値 | 意図 |
| --- | ---: | --- |
| 最大傾き角 `MAX_TILT_RAD` | 18° | 最大入力でも盤面はこれ以上傾かない |
| 重力の大きさ `GRAVITY_MAGNITUDE` | 12 | 幼児が目で追いかけられる速さで転がる、実スケールより弱い重力 |
| 最大傾きでの転がり加速度（概算） | 約2.65 | 一様な球の転がり加速度 `(5/7)·g·sinθ` から算出。1〜3の範囲に収まるようテストで固定 |
| デッドゾーン `TILT_DEADZONE` | 0.18 | 指を完全に中央へ戻せなくても「離したら止まる」を成立させる |
| 速度上限 `MAX_BALL_SPEED` | 5.4 | すり抜けと「速すぎて操作できない」を同時に防ぐ |
| 線形減衰 `BALL_LINEAR_DAMPING` | 0.42 | 転がり続けても加速し切らない |
| 角減衰 `BALL_ANGULAR_DAMPING` | 0.55 | 回転が暴れない |
| 入力の平滑化係数 `TILT_SMOOTHING_LAMBDA` | 9（1/秒） | 入力が飛んでも重力が階段状に切り替わらない |
| 見た目の傾き比率 `VISUAL_TILT_RATIO` | 0.62 | 物理の傾きより浅く見せて酔いにくくする |

反発は壁・床ともにほぼ殺しています（`BALL_RESTITUTION = 0.08`、`WALL_RESTITUTION = 0.02`）。壁で跳ね返って進行方向を見失わないようにするためです。摩擦は逆に高め（`BALL_FRICTION = 0.7`、`FLOOR_FRICTION = 0.85`）にして、滑るのではなく転がる感触にしています。

## 詰まらないための仕組み

- **外周壁**: ステージは必ず外周を`#`で囲み、盤面の外へ転がり出る通常経路を作りません。
- **場外判定からのスタート復帰**: `mazeRescue.ts`の`hasFallenOut`は、`FALL_OUT_Y = -6`より下に落ちた場合、または盤面境界の外側`1.5`（ワールド単位）を大きく超えた場合に場外と判定します。検出すると`useMazeEngine`が`rescueToStart`でボールをスタートへ戻し、`onRescue`コールバックで「スタートに もどったよ」を一瞬だけ表示します（ゲームは止めません）。
- **停滞検知からの弱いナッジ**: `updateStallTracker`は、入力の大きさが`STALL_TILT_THRESHOLD = 0.45`以上なのに速さが`STALL_SPEED = 0.12`未満の状態が`STALL_DURATION_MS = 1400`ms続いたら、傾けている方向へごく弱い力（`nudgeBall`、強さ`0.12`）を1回だけ加えます。通常の転がりには影響しない大きさで、幼児が「動かない」まま諦めないための保険です。
- **いつでも押せる「スタートに もどる」**: プレイ中は常時表示され、物理世界を作り直さずにボールだけをスタートへ戻します（`resetBallToStart`）。
- **ゴール後の「もういちど」**: `runId`を更新して`useMazeEngine`のエフェクトを丸ごと作り直し、物理世界・カメラ・傾き状態を最初の状態に揃えます。

## アクセシビリティと画面サイズ

- **キーボード操作**: 矢印キー／WASD（`TILT_KEY_CODES`）で操作でき、`FlagRollMazePlay.tsx`側でキー押下状態を集計して`TiltInput`へ変換します。矢印キーでのページスクロールは`preventDefault`で止め、タブを離れた（`blur`）ときは押しっぱなし状態をクリアします。
- **通知**: ゴール文言（「ゴール！ すごい！」）と場外復帰メッセージ（「スタートに もどったよ」）はいずれも`role="status"`と`aria-live="polite"`を付けています。
- **タップ領域**: 操作ボタンは`min-height: var(--tap-target-min)`。バーチャルスティックは`min(34vw, 148px)`（最小120px）で、規約の主操作64px以上を満たします。
- **`prefers-reduced-motion`**: バーチャルスティックのノブが指を離したあと中央へ戻る`transition`（`VirtualStick.module.css`）は`prefers-reduced-motion: reduce`で無効化されます。ボール自体の転がりはCSSアニメーションではなく物理演算そのもの（ゲームの本質的な動き）なので対象にしていません。全画面共通の`global.css`側の`prefers-reduced-motion`ルールもCSSの`transition`/`animation`を対象にしており、同じ扱いです。
- **狭い縦画面・低い横画面**: `FlagRollMazePlay.module.css`は`max-height: 560px`で説明文とキーボードヒントを非表示にし見出しを縮小、`max-width: 360px`でボタンの余白とフォントを詰めます。3Dシーンとカメラは`ResizeObserver`（未対応環境では`window`の`resize`）で追従し、`computeMazeCameraSetup`がその時点のaspectから盤面全体が収まる距離を再計算します。
- **バーチャルスティックの`aria-hidden`**: `VirtualStick`のルート要素は`aria-hidden="true"`です。矢印キー／WASDによるキーボード操作を別に用意しているポインタ専用の見た目のため、スクリーンリーダーには操作可能な要素として読み上げさせません。

## 素材

Phase 1は外部素材を一切使いません。盤面・壁・ゴール・ボールはすべてThree.jsのプリミティブ形状（`BoxGeometry` / `CylinderGeometry` / `SphereGeometry`）と単色の`MeshLambertMaterial`で表現しています。画像・音声などの新規バイナリアセットは追加していないため、`docs/CREDITS.md`への追記は不要です。

## PWA

追加の静的素材（画像・音声などのファイル）が無いため、`vite.config.ts`のWorkbox `globPatterns`の変更は不要です。Rapierのwasmは`rapier.mjs`へbase64で埋め込まれた形でJSバンドルの一部として配信され、既存の`domino-flag`（こっきドミノ）と同じインスタンス初期化コード（モジュール内で一度だけ`RAPIER.init()`する仕組み）を、それぞれのゲームが自分のモジュール内に持つ形で共有しています。

## Phase 2以降への引き継ぎ

- **ジャイロ入力**: Device Orientationのセンサー値から`TiltInput`を作る変換を1つ追加する。`mazePhysics.ts`・`mazeWorld.ts`など物理側は無変更で済む設計にしてある。
- **国旗ボール**: 現在は単色球のボールを、選んだ国旗を貼ったボールへ差し替える。
- **ステージ追加**: `mazeStage.ts`の文字グリッドを増やし、`createMazeStage`にステージ選択の`id`/`nameJa`を渡す形にする。`isMazeSolvable`で解けることを品質ゲートにする。
- **ギミック**: 分岐、加速レーン、ジャンプ台などのコース要素。
- **演出**: 効果音の追加、ゴール時のアニメーション、背景の作り込みなど。
